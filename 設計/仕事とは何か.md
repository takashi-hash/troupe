# Ichiza（一座）— 仕事とは何か

**版**: v2.0（2026-08-22。14枚を5枚に束ね直した。**1つの概念が6枚に散っていたのが、
ロールプレイ4回とも通らなかった原因**——足すたびに埋め落とすので、
「仕事に何を持たせるか」をこの1枚で閉じる）

**役目**: 仕事という語・その中身・守るべきもの・取りうる姿。**ここで閉じる。**

---

## 1. ドメインと中核

**仕事を落とさずに回し、判断を人に残すこと。**

| 分類 | 領域 | 扱い |
|---|---|---|
| **中核** | 仕事の一生／人の承認と差し戻し／終わったと言える根拠／業務ルールの版と有効化／**AI が仕事を1件こなす筋道** | 作り込む |
| **支援** | 題材ごとの業務ルールの中身／画面の見せかた | 薄く。**データで注ぐ** |
| **汎用** | 保存／周期で回す仕組み／**AI が常駐する仕組み**／排他制御／**LLM を呼ぶ道具**／画面の部品 | 買う |

### 公理 — 判断は人間

AI は作り、こなし、検査し、並べる。**決めない。**
承認・差し戻し・回答・有効化・打ち切りの5つは、人しか起こせない（**I7**）。

**AI から人への道は2つ。** 質問（材料が足りない）と見立て（読んだ結果と案）。
どちらも判断ではない。**見立てが無いと AI は数字しか出せない**——
「20回使い切りました」ではなく「20回とも同じ理由で落ちました。源の在りかが
変わった可能性が高い」と言えること。それがこの仕組みの値打ち。

### AI は2つに分かれる

| | どちらか |
|---|---|
| **LLM を呼ぶ道具**（モデル・API） | **外・汎用**。買う |
| **働き手としての AI**（担当を持ち、取り・尋ね・出し・落ち・見立てを書く） | **中・中核** |

分けないと後者が外へ出る。実際に出て、AI の操作の置き場が無くなった。

## 2. 語（**日本語⇄識別子の橋はここだけ**）

**業務の語だけを載せる。** パターンの名（値オブジェクト・集約・リポジトリ…）は
日本語の定訳のまま使い、**用語集には載せない**。

### 人と場

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 人 | 判断する者 | `Human` |
| AI | 仕事をこなす働き手。担当を持つ。**判断はしない** | `Agent` |
| 帳簿 | 起きたことと、いまの姿を持つ場。**書き換えない・消さない** | `Ledger` |

### 仕事

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 仕事 | 頼まれてから終わるまでの1件 | `Job` |
| 仕事の識別子 | 一意。あとから変えない | `JobId` |
| 作成元 | どこから生まれたか。**二度作らない鍵** | `Origin` |
| 依頼 | 人が「これをやって」と言った事実 | `Request` |
| 期日 | 終えるべき時刻 | `DueDate` |
| 確かめ期日 | 根拠が無いまま終えたとき、あとで確かめる時刻 | `RecheckDate` |
| 担当 | いま持っている者。人か AI | `Assignee` |
| 受け持ちの人 | 承認をし、AI の質問を受ける人。**版が決める** | `Owner` |
| 成果 | 仕事が生んだもの。出したら書き換えない | `Result` |
| 根拠 | 終わったと言える裏づけ。**源から読んだ引用**。AI の言葉は根拠にならない | `Evidence` |
| 承認 | 人が「進んでよい」と決めた事実 | `Approval` |
| 差し戻し | 人が「まだだ」と決めた事実 | `SendBack` |
| 質問 | 材料が足りないとき AI が尋ねること。**判断は求めない** | `Question` |
| 回答 | 人が答えた事実 | `Answer` |
| 見立て | AI が状況を読んだ結果と理由。**判断ではない** | `Assessment` |
| 使用上限 | 使ってよい回数と時間。**暴走を止める安全弁** | `Budget` |
| 使った量 | これまでに使った回数と秒 | `Spent` |

### 決まり

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 業務ルール | 繰り返しやる仕事の決まり。これが仕事を生む | `Rule` |
| 業務ルールの識別子 | 一意 | `RuleName` |
| 版 | 業務ルールの1つの姿。**積むだけ** | `Version` |
| **やること** | その仕事で何をするのか。**AI が読む指示** | `Instruction` |
| 受け入れ基準 | 何をもって成果とするか | `AcceptanceCriteria` |
| 周期 | 月か週 | `Cycle` |
| 対象期間 | その仕事が担当する期間 | `Period` |
| 源 | 材料の在りか。AI が読みに行く先 | `Source` |
| 有効 | その版でいま仕事を生してよい、という人の判断 | `Active` |
| 検査 | 成果が受け入れ基準を満たすかを機械で見ること。**止める力を持つ** | `Check` |
| LLM に問う | 源を読み、LLM に渡し、応答を受け取ること。**振り分けるのは仕様** | `consult` |
| やり直しの上限 | 何回までやり直してよいか。版が決める | `MaxRetries` |

### 使わない語

| 使わない | 代わりに | なぜ |
|---|---|---|
| タスク | 仕事 | 人が「仕事」と言う |
| 定義 | 業務ルール | 設計の語であって業務の語ではない |
| 証拠 | 根拠 | 同上 |
| 置き場・口・輪・手順・仕立て | **パターンの名をそのまま使う** | 役割の語を日本語にすると、そこからコードの名前を作ってしまう |

**1語1識別子。** 同じ語に2つの識別子を割り当てない。逆も同じ。

## 3. 値オブジェクト

**不正な値を存在させない。** 分類は名札で、**義務が本体**。

### 全部に共通の義務

| 共通の義務 | 壊しかた |
|---|---|
| 作るときに検証を通る | 不正な中身で作れたら赤 |
| **同じ中身なら等しい**。同じ辞書の鍵になる | 同じ中身の2つが等しくなければ赤 |
| **作ったあと書き換えられない** | 属性への代入が通ったら赤 |

### 一覧

| 値オブジェクト | 義務 | 壊しかた |
|---|---|---|
| `JobId` | 空でない。前後に空白が無い。あとから変えない | `JobId("")` が通ったら赤 |
| `RuleName` | 空でない | `RuleName("")` が通ったら赤 |
| `Human` | 名が空でない | 空で作れたら赤 |
| `Agent` | 名が空でない | 空で作れたら赤 |
| `Owner` | **`Human` そのもの**。AI は受け持ちの人になれない | `Agent` から作れたら赤 |
| `Assignee` | **`Human` か `Agent` のどちらか**。3つ目は無い | 素の文字列から作れたら赤 |
| `DueDate` | 時刻を持つ。**起点の時刻を受け取って比べる**（依頼発は依頼の時刻、業務ルール発は作られた時刻） | 起点より前で作れたら赤 |
| `RecheckDate` | 時刻を持つ。**期日より後**。**仕事が写した周期から決まる**（週次なら次の週）——AI が決めるのではない | 期日より前で作れたら赤 |
| `Budget` | 回数も秒も**1以上** | `Budget(calls=0)` が通ったら赤 |
| `Spent` | 回数も秒も**0以上**。上限とは別の値 | 負の値で作れたら赤 |
| `Period` | 月なら `2026-08`、週なら `2026-W34` の形だけ | `Period("来月")` が通ったら赤 |
| `Cycle` | 月か週のどちらか | 3つ目の値が通ったら赤 |
| `Instruction` | **空でない**。AI が読んで何をするか分かる文 | 空で作れたら赤 |
| `AcceptanceCriteria` | 空でない | 空で作れたら赤 |
| `Source` | 在りかが空でない | 空で作れたら赤 |
| `Origin` | 依頼発なら依頼の識別子、業務ルール発なら `RuleName`＋版の番号＋`Period`。**同じ中身なら同じ鍵の文字列** | 空で作れたら赤／同じ中身が違う鍵を出したら赤 |
| `Request` | 頼んだ人・時刻・中身を持つ | どれか欠けて作れたら赤 |
| `Result` | **在りかと中身**を持つ。どちらも空でない。出したあと差し替えられない | 中身空で作れたら赤 |
| `Evidence` | **源から読んだ引用が空でない**。読んだ先を指している | 引用の空な根拠が作れたら赤 |
| `Approval` | **誰が**と**いつ**を両方持つ | 片方空で作れたら赤 |
| `SendBack` | 理由が空でない | 理由なしで作れたら赤 |
| `Question` | 尋ねる中身が空でない。**相手は仕事の受け持ちの人**——AI が選ばない | 中身空で作れたら赤 |
| `Answer` | 答えた人と中身を持つ | どちらか欠けて作れたら赤 |
| `Assessment` | 読んだ結果と、**そう読んだ理由**を両方持つ | 理由なしで作れたら赤 |
| `Version` | 番号は1以上。**やること・受け入れ基準・周期・終えるまでの日数・使用上限・受け持ちの人・源・やり直しの上限**を必ず持つ | どれか欠けて作れたら赤 |

**版が「やること」を持つのが要。** 持たないと **AI は何をすればよいか永久に知れない**
（ロールプレイ4回目で見つかった。中核の欠け）。

## 4. エンティティと集約

### エンティティは2つ

| | 同一性 |
|---|---|
| 仕事 `Job` | `JobId` |
| 業務ルール `Rule` | `RuleName` |

### 仕事が持つもの（**どの状態でも**）

**状態ごとに書き分けると、次の遷移で材料が生える。** 共通はここに1度だけ書く。

| 持ちもの | 出どころ |
|---|---|
| `Origin` | 立てた者が決める |
| 生まれた版（`RuleName`＋版の番号） | 生成の時点で固定。あとで版が積まれても書き換えない |
| `Instruction`・`AcceptanceCriteria`・`Owner`・`Budget`・`Source`・`Cycle`・`MaxRetries` | **固定した版から写す**（いまの版からは取らない） |
| やり直した回数 | 0 で生まれる。**どの状態でも持つ**——失敗した状態だけに持たせると、やり直すたびに落ちる |
| `DueDate` | 起点の時刻 ＋ 版の日数 |
| `Spent` | `Spent(0, 0)` で生まれる |
| 成果の在りか・根拠の在りか | 出てから持つ（それまでは空）。**状態ごとに書き分けない**——書き分けると次の遷移で落ちる |
| `Period` | 業務ルール発のみ |

**写すのであって、指すのではない。** 版をまたいで読みに行くと、
1回の書き込みで2つの集約を触ることになる。

### 業務ルールが持つもの

| 持ちもの | 決まり |
|---|---|
| `RuleName` | 同一性 |
| 版の列 | **積むだけ**。減らせない・書き換えられない |
| 有効な版の番号 | **0か1つ**。版2を有効にすると版1は自動で無効になる |
| 有効にした人と時刻 | 人だけが有効にできる（I7） |

### 集約は2つ

**境界が要ると言えた不変条件からしか作らない。**

| 集約 | 鍵 | 要求した不変条件 | 1回の書き込みで守るもの |
|---|---|---|---|
| **仕事** `Job` | `JobId` | **I1** | 姿の変化と、その理由のドメインイベント |
| **業務ルール** `Rule` | `RuleName` | **I2** | 版の追加と、追加したドメインイベント |

**集約にしないもの**: 人・AI（値で足りる）／成果・根拠・質問と回答・見立て（積むだけの列。
**在りかで指す**）／出来事（集約の中に積まれる）。
**中核であることと集約であることは別**——AI は中核だが集約ではない。

## 5. 不変条件（**正本**）

「境界が要る」とは**2つ以上を1回の書き込みで守らないと壊れる**こと。

| # | 不変条件 | 境界 | 守る場所 | 即時／結果 | 執行者 | 壊しかた |
|---|---|---|---|---|---|---|
| **I1** | 状態が変わったら、理由のドメインイベントが必ず一緒に残る | **要る** | 書き込みの門 | 即時 | まだ居ない | 出来事なしで状態を書く |
| **I2** | 版は積むだけ。追加と出来事が一緒に残る | **要る** | 書き込みの門 | 即時 | まだ居ない | 版を1つ消して書く |
| **I3** | 同じ作成元から仕事は二度作られない | 要らない | 帳簿の一意の鍵 | 即時 | まだ居ない | 同じ鍵で2回作る |
| **I4** | 承認なしに先へ進まない | 要らない | 型（承認済みが `Approval` を必ず持つ） | 即時 | まだ居ない | 承認を持たずに作る |
| **I5** | 終わったと言うには、根拠か確かめ期日が要る | 要らない | 型（終わりが2種だけ） | 即時 | まだ居ない | 両方なしで作る |
| **I6** | 承認できるのは**受け持ちの人だけ** | 要らない | 承認の操作 | 即時 | まだ居ない | 別の人で承認する |
| **I7** | **人しか起こせない5操作は、AI から呼べない**（承認・差し戻し・回答・有効化・打ち切り）。**公理の執行者** | 要らない | 5つの操作それぞれ | 即時 | まだ居ない | AI から承認を呼ぶ |
| **I8** | 業務ルールが有効なら、その対象期間の仕事が必ず存在する | 要らない | 周期で回る突合 | **結果** | まだ居ない | 突合を止めて1周期待つ |
| **I9** | 期日の過ぎた仕事のうち、**人がいま押せる操作を持つもの**は必ず今日に出る | 要らない | 今日の判定 | **結果** | まだ居ない | 判定から期日の行を消す |
| **I10** | 帳簿は自分の形を名乗り、合わなければ開かない | 要らない | 開くときの検査 | 即時 | まだ居ない | 番号を変えて開く |
| **I11** | 検査は**壊して赤を見てから**使う | 要らない | 人の手 | **実測** | 人（置いた日） | — |
| **I12** | 期日は**起点の時刻より後** | 要らない | 仕事を作る操作 | 即時 | まだ居ない | 起点より前で作る |
| **I13** | AI が**姿を変えられる**のは自分が担当の仕事だけ（**取るだけは別**——取る前は担当ではない。**見立てを書くのも別**——落ちた仕事・終わった仕事こそ見立てが要る） | 要らない | 取ったあとの姿を変える操作 | 即時 | まだ居ない | 別の担当の仕事の姿を変える |
| **I14** | 使った量は**使用上限を超えない**。超える前に AI は必ず**見立てを書く** | 要らない | 使った量を積む操作 | 即時 | まだ居ない | 上限を超えて積む |
| **I15** | **生の応答が帳簿へ入らない**——腐敗防止層が整え、成果・質問・見立ての**どれか1つ**になってから入る。**どれになるかは domain の仕様が決める** | 要らない | 腐敗防止層＋仕様 | 即時 | まだ居ない | 生の応答をそのまま成果にする |

**即時があることは、結果を要らなくしない。** 型はコードの道を守り、結果は**帳簿そのもの**を守る。
帳簿は道具より長生きする。

## 6. 状態と遷移（**正本**）

### 状態

**「必ず持つもの」の欄には、§4 の共通に足すもの・持ってはいけないものだけを書く。**

| 状態 | 足して持つもの | 持ってはいけないもの |
|---|---|---|
| **作られた** `Created` | — | 担当 |
| **着手できる** `Ready` | — | 担当・承認 |
| **実行中** `InProgress` | 担当 | 承認 |
| **答え待ち** `AwaitingAnswer` | 担当・**質問の在りか** | 承認 |
| **提出済み** `Submitted` | 担当。**成果の在りかが空でない** | 承認・検査の結果 |
| **承認待ち** `AwaitingApproval` | **担当が `Owner`**（I6）・成果の在りか | 承認 |
| **承認済み** `Cleared` | **承認**・成果の在りか | — |
| **失敗した** `Failed` | **落ちた中身** | 担当 |
| **終わった（確かめ待ち）** `FinishedPendingRecheck` | 承認・**確かめ期日** | 根拠の在りか |
| **終わった** `Finished` | 承認。**根拠の在りかが空でない**。**終点** | — |
| **打ち切られた** `Abandoned` | 打ち切った人・**理由**。**終点** | — |

### 遷移

**行けない遷移は書かない。型が作らせない。**

| から | へ | 操作 | 残る出来事 | 誰が |
|---|---|---|---|---|
| （無い） | 作られた | 頼む `request` | `JobRequested`＋`JobCreated` | 人 |
| （無い） | 作られた | 作る `create` | `JobCreated` | 時計 |
| 作られた | 着手できる | 配る `hand_out` | `JobHandedOut` | 時計 |
| 着手できる | 実行中 | 着手する `start` | `JobStarted` | **取ろうとする AI**（まだ担当ではない） |

| 実行中 | 着手できる | 手放す `release` | `JobReleased` | 担当 |
| 実行中 | 着手できる | 時間切れを戻す `return_timed_out` | `JobTimedOut` | 時計 |
| 実行中 | 答え待ち | 尋ねる `ask` | `QuestionAsked` | AI |
| 答え待ち | **着手できる** | 答える `answer` | `QuestionAnswered` | **人** |
| 実行中 | 提出済み | 出す `submit` | `ResultSubmitted` | 担当 |
| 実行中 | 失敗した | 落ちる `fail` | `JobFailed` | AI |
| 実行中 | 失敗した | **使い切る** `exhaust` | `JobFailed`（使用上限に達した） | AI（`spend` が I14 で止めたとき） |
| 提出済み | 承認待ち | 検査を回す `run_check`（通った） | `CheckPassed`（誰へ担当が移ったか） | 時計 |
| 提出済み | 着手できる | 検査を回す `run_check`（止まった） | `CheckStopped`（理由）＋`Retried` | 時計 |
| 承認待ち | 承認済み | 承認する `approve` | `Approved` | **人**（受け持ちの人） |
| 承認待ち | 着手できる | 差し戻す `send_back` | `SentBack` | **人** |
| 実行中 | 着手できる | 差し戻す `send_back` | `SentBack` | **人**（見立てを読んで） |
| 実行中 | 打ち切られた | 打ち切る `abandon` | `Abandoned` | **人**（見立てを読んで） |
| 失敗した | 着手できる | 失敗を仕分ける `sort_failures` | `Retried` | 時計 |
| 失敗した | 失敗した | **人へ回す** `hand_over` | `AssessmentWritten` | AI（上限に達した・やり直しが尽きた） |
| 失敗した | 着手できる | 差し戻す `send_back` | `SentBack` | **人** |
| 失敗した | 打ち切られた | 打ち切る `abandon` | `Abandoned` | **人** |
| 承認済み | 終わった | 確かめる `confirm`（根拠あり） | `JobFinished` | 時計 |
| 承認済み | 終わった（確かめ待ち） | 確かめる `confirm`（根拠なし） | `JobFinished` | 時計 |
| 終わった（確かめ待ち） | 終わった | 確かめる `confirm`（根拠あり） | `JobFinished` | 時計 |
| 終わった（確かめ待ち） | 着手できる | 差し戻す `send_back` | `SentBack` | **人** |

**答えたら「着手できる」へ戻す。** 実行中へ戻すと、答えを待っているあいだに
担当が外れた仕事を誰も拾えない（AI は着手できるを取りに来る）。
**戻り先はすべて「着手できる」**——覚えるものを増やさない。

### 姿は変わるが、状態は変わらない操作

使った量が 0→3 になっても「実行中」のまま。**遷移表には載せない。**

| 仕掛け | 壊しかた |
|---|---|
| **同じ状態の型を返す関数**として書く。返すのは（同じ状態, 出来事）の対 | 状態だけ返す形が書けたら赤 |
| 例外は3つだけ——`DueDatePassed`・`Spent`・`AssessmentWritten` | 4つ目を遷移表の外で刻めたら赤 |

---

## 7. 型で殺す

### 禁止値

| 書けてはいけない値 | 何が拒むか |
|---|---|
| 0や負の使用上限 | `Budget` |
| 負の使った量 | `Spent` |
| 空の担当・空の名前 | `Assignee`・`JobId`・`RuleName` |
| 起点より前の期日 | `DueDate` |
| 形の違う対象期間 | `Period` |
| 引用の空な根拠 | `Evidence` |
| 誰かいつが欠けた承認 | `Approval` |
| 理由の無い差し戻し・理由の無い見立て | `SendBack`・`Assessment` |
| **やることの空な版** | `Version` |
| AI を受け持ちの人にする | `Owner` |

### 禁止状態

| 書けてはいけない状態 | 何が拒むか |
|---|---|
| 承認なしの承認済み | 承認済みが `Approval` を必ず持つ |
| 根拠も確かめ期日も無い終わり | 終わりが2種だけ |
| 担当の無い実行中 | 実行中が担当を必ず持つ |
| 質問の無い答え待ち | 答え待ちが質問の在りかを必ず持つ |
| 承認を持ったまま着手できるへ戻る | 着手できるが承認を持たない型 |
| 版が減った業務ルール | 書き込みで前の版列と突き合わせる |
| 急ぎの印 | **そういう欄が無い**。急ぎは「期日が今日」で表す |
