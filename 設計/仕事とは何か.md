# Ichiza（一座）— 仕事とは何か

**版**: v2.0（2026-08-22。14枚を5枚に束ね直した。**1つの概念が6枚に散っていたのが、
ロールプレイ4回とも通らなかった原因**——足すたびに埋め落とすので、
「仕事に何を持たせるか」をこの1枚で閉じる）

**役目**: 仕事という語・その中身・守るべきもの・取りうる姿。**ここで閉じる。**

---

## 1. ドメインと中核

**仕事を落とさずに回し、判断を人に残すこと。**

| 分類 | 領域 | 扱い |
|---|---|---|
| **中核** | 仕事の一生／人の承認と差し戻し／終わったと言える根拠／業務ルールの版と有効化／**AI が仕事を1件こなす筋道** | 作り込む |
| **支援** | 題材ごとの業務ルールの中身／画面の見せかた | 薄く。**データで注ぐ** |
| **汎用** | 保存／周期で回す仕組み／**AI が常駐する仕組み**／排他制御／**LLM を呼ぶ道具**／画面の部品 | 買う |

### 公理 — 判断は人間

AI は作り、こなし、検査し、並べる。**決めない。**
承認・差し戻し・回答・有効化・停止・打ち切りの6つは、人しか起こせない（**I7**）。

**AI から人への道は2つ。** 質問（材料が足りない）と見立て（読んだ結果と案）。
どちらも判断ではない。**見立てが無いと AI は数字しか出せない**——
「20回使い切りました」ではなく「20回とも同じ理由で落ちました。源の在りかが
変わった可能性が高い」と言えること。それがこの仕組みの値打ち。

### AI は2つに分かれる

| | どちらか |
|---|---|
| **LLM を呼ぶ道具**（モデル・API） | **外・汎用**。買う |
| **働き手としての AI**（担当を持ち、取り・尋ね・出し・落ち・見立てを書く） | **中・中核** |

分けないと後者が外へ出る。実際に出て、AI の操作の置き場が無くなった。

## 2. 語（**日本語⇄識別子の橋はここだけ**）

**業務の語だけを載せる。** パターンの名（値オブジェクト・集約・リポジトリ…）は
日本語の定訳のまま使い、**用語集には載せない**。

### 人と場

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 人 | 判断する者 | `Human` |
| AI | 仕事をこなす働き手。担当を持つ。**判断はしない** | `Agent` |
| 帳簿 | 起きたことと、いまの姿を持つ場。**書き換えない・消さない** | `Ledger` |

### 仕事

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 仕事 | 頼まれてから終わるまでの1件 | `Job` |
| 仕事の識別子 | 一意。あとから変えない | `JobId` |
| 作成元 | どこから生まれたか。**二度作らない鍵** | `Origin` |
| 依頼 | 人が「これをやって」と言った事実 | `Request` |
| 期日 | 終えるべき時刻 | `DueDate` |
| 確かめ期日 | 根拠が無いまま終えたとき、あとで確かめる時刻 | `RecheckDate` |
| 担当 | いま持っている者。人か AI | `Assignee` |
| 起こす者 | その手を起こした者。人・AI・時計のどれか。**担当とは別**（画面は起こさない——開いた人が起こす者） | `Actor` |
| 受け持ちの人 | 承認をし、AI の質問を受ける人。**版が決める** | `Owner` |
| 成果 | 仕事が生んだもの。出したら書き換えない | `Result` |
| 根拠 | 終わったと言える裏づけ。**源から読んだ引用**。AI の言葉は根拠にならない | `Evidence` |
| 承認 | 人が「進んでよい」と決めた事実 | `Approval` |
| 差し戻し | 人が「まだだ」と決めた事実 | `SendBack` |
| 質問 | 材料が足りないとき AI が尋ねること。**判断は求めない** | `Question` |
| 回答 | 人が答えた事実 | `Answer` |
| 見立て | AI が状況を読んだ結果と理由。**判断ではない** | `Assessment` |
| 使用上限 | 使ってよい回数と時間。**暴走を止める安全弁** | `Budget` |
| 使った量 | これまでに使った回数と秒 | `Spent` |
| 整えた応答 | LLM の応答を腐敗防止層が整えたもの。**印**と本文 | `Reply` |

### 決まり

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 業務ルール | 繰り返しやる仕事の決まり。これが仕事を生む | `Rule` |
| 業務ルールの識別子 | 一意 | `RuleName` |
| 版 | 業務ルールの1つの姿。**積むだけ** | `Version` |
| **やること** | その仕事で何をするのか。**AI が読む指示** | `Instruction` |
| 受け入れ基準 | 何をもって成果とするか。**必ず含む語**（機械が見る——**源に字面どおり在る語から選ぶ**。見比べは字面）と説明の文（人と AI が読む） | `AcceptanceCriteria` |
| 周期 | 月か週 | `Cycle` |
| 対象期間 | その仕事が担当する期間 | `Period` |
| 源 | 材料の在りか。AI が読みに行く先 | `Source` |
| 有効 | その版でいま仕事を生してよい、という人の判断 | `Active` |
| 検査 | 成果が受け入れ基準を満たすかを機械で見ること。**止める力を持つ** | `Check` |
| LLM に問う | 源を読み、LLM に渡し、応答を受け取ること。**振り分けるのは仕様** | `consult` |
| やり直しの上限 | 何回までやり直してよいか。版が決める | `MaxRetries` |

### 使わない語

| 使わない | 代わりに | なぜ |
|---|---|---|
| タスク | 仕事 | 人が「仕事」と言う |
| 定義 | 業務ルール | 設計の語であって業務の語ではない |
| 証拠 | 根拠 | 同上 |
| 置き場・口・輪・手順・仕立て | **パターンの名をそのまま使う** | 役割の語を日本語にすると、そこからコードの名前を作ってしまう |

**1語1識別子。** 同じ語に2つの識別子を割り当てない。逆も同じ。**欄の名も同じ**——中身 `body`・誰が `by`・いつ `at`・起点 `start`・基準 `after`・名 `name`・鍵 `key`・理由 `reason`・引用 `quote`・相手 `to`・識別子の文字 `text`・終えるまでの日数 `days`。

## 3. 値オブジェクト

**不正な値を存在させない。** 分類は名札で、**義務が本体**。

### 全部に共通の義務

| 共通の義務 | 壊しかた |
|---|---|
| 作るときに検証を通る | 不正な中身で作れたら赤 |
| **同じ中身なら等しい**。同じ辞書の鍵になる | 同じ中身の2つが等しくなければ赤 |
| **作ったあと書き換えられない** | 属性への代入が通ったら赤 |

### 一覧

| 値オブジェクト | 義務 | 壊しかた |
|---|---|---|
| `JobId` | 空でない。前後に空白が無い。あとから変えない | `JobId("")` が通ったら赤 |
| `RuleName` | 空でない | `RuleName("")` が通ったら赤 |
| `Human` | 名が空でない | 空で作れたら赤 |
| `Agent` | 名が空でない | 空で作れたら赤 |
| `Owner` | **`Human` そのもの**。AI は受け持ちの人になれない | `Agent` から作れたら赤 |
| `Assignee` | **`Human` か `Agent` のどちらか**。3つ目は無い | 素の文字列から作れたら赤 |
| `DueDate` | 時刻を持つ。**起点の時刻を受け取って比べる**（依頼発は依頼の時刻、業務ルール発は作られた時刻） | 起点より前で作れたら赤 |
| `RecheckDate` | 時刻を持つ。**期日より後**。**前の確かめ期日（無ければ期日）＋写した周期**——AI が決めるのではない。送るたびに先へ進む | 期日より前で作れたら赤／送って進まなかったら赤 |
| `Budget` | 回数も秒も**1以上** | `Budget(calls=0)` が通ったら赤 |
| `Spent` | 回数も秒も**0以上**。上限とは別の値 | 負の値で作れたら赤 |
| `Period` | 月なら `2026-08`、週なら `2026-W34` の形だけ。**週の年は ISO**——年始の日が前年の週に属することがある | `Period("来月")` が通ったら赤 |
| `Cycle` | 月か週のどちらか | 3つ目の値が通ったら赤 |
| `Instruction` | **空でない**。AI が読んで何をするか分かる文 | 空で作れたら赤 |
| `AcceptanceCriteria` | **2つに分かれる**。①**必ず含む語**の列（空でない。**機械が見る**）②説明の文（**人と AI が読む**）。①に `{対象期間}` と書ける——**写すときに `Period` で開く**ので、検査に届く時点では固定の文字列 | ①が空で作れたら赤／開かれていない `{` が検査に届いたら赤 |
| `Source` | 在りかが空でない | 空で作れたら赤 |
| `Origin` | 依頼発なら依頼の識別子、業務ルール発なら `RuleName`＋版の番号＋`Period`（**患者ごとに展開する版は患者記号も**）。**同じ中身なら同じ鍵の文字列** | 空で作れたら赤／同じ中身が違う鍵を出したら赤 |
| `Request` | 頼んだ人・時刻・中身を持つ | どれか欠けて作れたら赤 |
| `Result` | **中身が空でない**。出したあと差し替えられない。**在りかは持たない**——積んだ Store が返し、仕事が持つ | 中身空で作れたら赤／在りかの欄があったら赤 |
| `Evidence` | **源から読んだ引用が空でない**。**どの源から読んだか**を持つ（積んだ先ではない）。**切り出さない**——選んだ瞬間に選別という判断が入る。畳むのは画面の見せかたの仕事 | 引用の空な根拠が作れたら赤 |
| `Approval` | **誰が**と**いつ**を両方持つ | 片方空で作れたら赤 |
| `SendBack` | 理由が空でない | 理由なしで作れたら赤 |
| `Question` | 尋ねる中身が空でない。**相手は仕事の受け持ちの人**——AI が選ばない | 中身空で作れたら赤 |
| `Reply` | 本文が空でない。**印は成果・質問・どちらでもない の3つのどれか**。**印を名乗るのは LLM**（adapters は運ぶだけ）。**印は自己申告——仕様が検める** | 印の無い応答が仕様に届いたら赤 |
| `Actor` | **人・AI・時計の3つのどれか**。素の文字列から作れない | 4つ目が作れたら赤／素の文字列から作れたら赤 |
| `Clock` | 時計——起こす者にはなるが**担当にはならない**。中身は無い | 名を付けられたら赤（時計は1つ、名で区別しない） |
| `Answer` | 答えた人と中身を持つ | どちらか欠けて作れたら赤 |
| `Assessment` | 読んだ結果と、**そう読んだ理由**を両方持つ | 理由なしで作れたら赤 |
| `Version` | 番号は1以上。**やること・受け入れ基準・周期・終えるまでの日数・使用上限・受け持ちの人・源・やり直しの上限**を必ず持つ | どれか欠けて作れたら赤 |
| `Copied` | 写すものの束——共通の持ちもの＋終えるまでの日数（正本は §4）。**版そのものは渡さない** | どれか欠けて作れたら赤 |
| `TodayMaterial` | 今日の材料——**仕様が見る domain の値**（欄の正本は[人に見えるもの §2](人に見えるもの.md)） | **押せることの欄を持ったら赤**——材料と行は別物 |

**版が「やること」を持つのが要。** 持たないと **AI は何をすればよいか永久に知れない**
（ロールプレイ4回目で見つかった。中核の欠け）。

## 4. エンティティと集約

### エンティティは2つ

| | 同一性 |
|---|---|
| 仕事 `Job` | `JobId` |
| 業務ルール `Rule` | `RuleName` |

### 仕事が持つもの（**どの状態でも**）

**状態ごとに書き分けると、次の遷移で材料が生える。** 共通はここに1度だけ書く。

| 持ちもの | 出どころ |
|---|---|
| `Origin` | 立てた者が決める |
| 生まれた版（`RuleName`＋版の番号） | 生成の時点で固定。あとで版が積まれても書き換えない |
| `Instruction`・`AcceptanceCriteria`・`Owner`・`Budget`・`Source`・`Cycle`・`MaxRetries` | **固定した版から写す**（いまの版からは取らない）。写すとき `AcceptanceCriteria` の `{対象期間}` を `Period` で開く |
| やり直した回数 | 0 で生まれる。**どの状態でも持つ**。`Retried` が +1 する。**`SentBack` は 0 に戻す**（+1 しない） |
| `DueDate` | 起点の時刻 ＋ 版の日数 |
| `Spent` | `Spent(0, 0)` で生まれる。**`SentBack` は `Spent(0, 0)` に戻す**（どの状態からでも） |
| 成果の在りか・根拠の在りか | 出てから持つ（それまでは空）。**状態ごとに書き分けない**——書き分けると次の遷移で落ちる |
| `Period` | 業務ルール発のみ |

**写すのであって、指すのではない**——指すと1回の書き込みで2つの集約を触る。

### 業務ルールが持つもの

| 持ちもの | 決まり |
|---|---|
| `RuleName` | 同一性 |
| 版の列 | **積むだけ**。減らせない・書き換えられない |
| 有効な版の番号 | **0か1つ**。版2を有効にすると版1は自動で無効になる |
| 有効にした人と時刻 | 人だけが有効にできる（I7） |

### 集約は2つ

**境界が要ると言えた不変条件からしか作らない。**

| 集約 | 鍵 | 要求した不変条件 | 1回の書き込みで守るもの |
|---|---|---|---|
| **仕事** `Job` | `JobId` | **I1** | 姿の変化と、その理由のドメインイベント |
| **業務ルール** `Rule` | `RuleName` | **I2** | 版の追加と、追加したドメインイベント |

**集約にしないもの**: 人・AI（値で足りる）／成果・根拠・質問と回答・見立て（積むだけの列。
**在りかで指す**）／出来事（集約の中に積まれる）。
**中核であることと集約であることは別**——AI は中核だが集約ではない。

## 5. 不変条件（**正本**）

「境界が要る」とは**2つ以上を1回の書き込みで守らないと壊れる**こと。

| # | 不変条件 | 境界 | 守る場所 | 即時／結果 | 執行者 | 壊しかた |
|---|---|---|---|---|---|---|
| **I1** | 状態が変わったら、理由のドメインイベントが必ず一緒に残る | **要る** | 書き込みの門 | 即時 | 帳簿の門（`save` が対しか受けない）＋操作の返りの型 | 出来事なしで状態を書く |
| **I2** | 版は積むだけ。追加と出来事が一緒に残る | **要る** | 書き込みの門 | 即時 | `SqliteRules` の突き合わせ | 版を1つ消して書く |
| **I3** | 同じ作成元から仕事は二度作られない | 要らない | 帳簿の一意の鍵 | 即時 | 帳簿の一意の鍵（作成元） | 同じ鍵で2回作る |
| **I4** | 承認なしに先へ進まない | 要らない | 型（承認済みが `Approval` を必ず持つ） | 即時 | 型（承認済みが `Approval` を必ず持つ） | 承認を持たずに作る |
| **I5** | 終わったと言うには、根拠か確かめ期日が要る | 要らない | 型（終わりが2種だけ） | 即時 | 型（終わりが2種だけ） | 両方なしで作る |
| **I6** | 承認できるのは**受け持ちの人だけ** | 要らない | 承認の操作 | 即時 | `approve` の検め＋承認待ちの担当の型 | 別の人で承認する |
| **I7** | **人しか起こせない6操作は、AI から呼べない**（承認・差し戻し・回答・有効化・停止・打ち切り）。**公理の執行者** | 要らない | 6つの操作それぞれ | 即時 | `by` の型が `Human`＋突合 | AI から承認を呼ぶ |
| **I8** | 業務ルールが有効なら、その対象期間の仕事が必ず存在する | 要らない | 周期で回る突合 | **結果** | 時計の `create`＋`audit`（周期で回る突合） | 突合を止めて1周期待つ |
| **I9** | 期日の過ぎた仕事のうち、**人がいま押せる操作を持つもの**は必ず今日に出る | 要らない | 今日の判定 | **結果** | `judge_today` とその試験 | 判定から期日の行を消す |
| **I10** | 帳簿は自分の形を名乗り、合わなければ開かない | 要らない | 開くときの検査 | 即時 | `open_ledger` の形の番号 | 番号を変えて開く |
| **I11** | 検査は**壊して赤を見てから**使う | 要らない | 人の手 | **実測** | 人（置いた日） | — |
| **I12** | 期日は**起点の時刻より後** | 要らない | 仕事を作る操作 | 即時 | `DueDate` の型 | 起点より前で作る |
| **I13** | AI が**姿を変えられる**のは自分が担当の仕事だけ（**取るだけは別**——取る前は担当ではない。**見立てを書くのも別**——落ちた仕事・終わった仕事こそ見立てが要る） | 要らない | 取ったあとの姿を変える操作 | 即時 | **`consult`・`release` の検め（名乗り＝担当）** | 別の担当の仕事の姿を変える |
| **I14** | 使った量は**使用上限を超えない** | 要らない | 使った量を積む操作 | 即時 | `spend` と `Spent.within` の試験 | 上限を超えて積む |
| **I15** | **上限に触れた仕事・やり直しが尽きた仕事には、必ず見立てが在る** | 要らない | **AI の巡回** | **結果** | 巡回＋見立てを書くべきかの仕様 | 尽きた仕事を1周期放置して見立てが0件 |
| **I16** | **生の応答が帳簿へ入らない**——腐敗防止層が `Reply` に整え（**印を運ぶのも形のうち**）、成果・質問・見立ての**どれか1つ**になってから入る。**どれになるかは domain の仕様が決める——LLM の名乗りは鵜呑みにしない** | 要らない | 腐敗防止層＋仕様 | 即時 | `LlmPort` の型＋印の検め | 生の応答をそのまま成果にする |

**即時があることは、結果を要らなくしない。** 型はコードの道を守り、結果は**帳簿そのもの**を守る。
帳簿は道具より長生きする。

## 6. 状態と遷移（**正本**）

### 状態

**「必ず持つもの」の欄には、§4 の共通に足すもの・持ってはいけないものだけを書く。**

| 状態 | 足して持つもの | 持ってはいけないもの |
|---|---|---|
| **作られた** `Created` | — | 担当 |
| **着手できる** `Ready` | — | 担当・承認 |
| **実行中** `InProgress` | 担当 | 承認 |
| **答え待ち** `AwaitingAnswer` | 担当（質問の本文は出来事 `QuestionAsked` が正本） | 承認 |
| **提出済み** `Submitted` | 担当。**成果の在りかが空でない** | 承認・検査の結果 |
| **承認待ち** `AwaitingApproval` | **担当が `Owner`**（I6）・成果の在りか | 承認 |
| **承認済み** `Cleared` | **承認**・成果の在りか | — |
| **失敗した** `Failed` | **落ちた中身** | 担当 |
| **終わった（確かめ待ち）** `FinishedPendingRecheck` | 承認・**確かめ期日** | 根拠の在りか |
| **終わった** `Finished` | 承認。**根拠の在りかが空でない**。**終点** | — |
| **打ち切られた** `Abandoned` | 打ち切った人・**理由**。**終点** | — |

### 遷移

**行けない遷移は書かない。型が作らせない。**

| から | へ | 操作 | 残る出来事 | 誰が |

| 答え待ち | **着手できる** | 答える `answer` | `QuestionAnswered` | **人** |

| 実行中 | 失敗した | 落ちる `fail` | `JobFailed` | AI |

### 姿は変わるが、状態は変わらない操作

使った量が 0→3 になっても「実行中」のまま。**遷移表には載せない。**

| 仕掛け | 壊しかた |
|---|---|
| **同じ状態の型を返す関数**として書く。返すのは（同じ状態, 出来事）の対 | 状態だけ返す形が書けたら赤 |
| 遷移表の外で刻めるのは——`DueDatePassed`・`SpentIncreased`・`AssessmentWritten`・`DraftDelivered` だけ | 列に無い出来事を遷移表の外で刻めたら赤 |

## 7. 型で殺す

### 禁止値

| 書けてはいけない値 | 何が拒むか |
|---|---|
| 0や負の使用上限 | `Budget` |
| 負の使った量 | `Spent` |
| 空の担当・空の名前 | `Assignee`・`JobId`・`RuleName` |
| 起点より前の期日 | `DueDate` |
| 形の違う対象期間 | `Period` |
| 引用の空な根拠 | `Evidence` |
| 誰かいつが欠けた承認 | `Approval` |
| 理由の無い差し戻し・理由の無い見立て | `SendBack`・`Assessment` |
| **やることの空な版** | `Version` |
| AI を受け持ちの人にする | `Owner` |
| AI が業務ルールを有効にした姿 | `Rule`（有効にした人の欄が人だけ） |

### 禁止状態

| 書けてはいけない状態 | 何が拒むか |
|---|---|
| 承認なしの承認済み | 承認済みが `Approval` を必ず持つ |
| 根拠も確かめ期日も無い終わり | 終わりが2種だけ |
| 担当の無い実行中 | 実行中が担当を必ず持つ |
| 質問の無い答え待ち | 尋ねるが空でない質問（値）を必ず受け、`QuestionAsked` を必ず刻む（I2） |
| 承認を持ったまま着手できるへ戻る | 着手できるが承認を持たない型 |
| 版が減った業務ルール | 書き込みで前の版列と突き合わせる |
| 急ぎの印 | **そういう欄が無い**。急ぎは「期日が今日」で表す |
