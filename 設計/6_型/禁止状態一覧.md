# Ichiza（一座）— 禁止状態一覧

**版**: v2.1（2026-08-21。v2.1: 適用を飛ばした完了を禁止に。v2.0: 術語を識別子に統一——tests/ の docstring と1対1）
**状態**: **有効になった**（2026-08-21、人が有効化した）

作れてはいけない状態と、**それを書けなくしている型の構造**の対応。ここにある禁止は全部「注意書き」ではなく「そもそも書けない」。

---

| 作れてはいけない状態 | なぜ書けないか（[状態モデル](状態モデル.md)のどこが殺すか） |
|---|---|
| Checkpoint なしの IrreversibleApply | IrreversibleApply が **ApprovalRecord を必ず持つ**。無しでは値が作れない |
| 担当外の approve | approve の呼べる者が **Checkpoint が持つ assignee_id の本人だけ** |
| Evidence の ReadPort があるのに Evidence なしの Closed | Closed は2種だけ——ClosedWithEvidence{evidence_ref} か ClosedBySelfReport{recheck_deadline}。どちらでもない Closed は存在しない |
| 緊急フラグ | どの型にもその欄が**無い**。急ぎは時刻の対（今・今日）でしか書けない |
| 却下済み Proposal の再出現 | Proposal の同一性が Fingerprint。却下は終端状態で、同じ Fingerprint は却下のまま（歩4） |
| Lease を持たない Running／Lease を持つ Ready | Lease は Running だけが持つ材料。他の State に Lease の欄が無い |
| Briefing の無い Ready | Ready{Briefing}——Briefing が値の材料。dispatch の Check が解決済みだけを承認する |
| Origin の無い Job | Origin は Core の必須材料。全 State が持つ |
| Check の「差し戻し」・Review の「止め」 | CheckResult と ReviewResult は**別の型**。Check に Returned は無く、Review に Blocked は無い |
| EnvironmentFailure が Human に上がる／ContentFailure が自動 retry される | Failure が2つに割れ、retry できるのは EnvironmentFailure{残りあり} だけ |
| 人の記憶を指す Briefing | Briefing の参照は Ledger と Source しか指せない（I7、歩4） |
| 二重に作成される月次 Job | Origin が Reconciliation の冪等の鍵——同じ Origin はもう在るか、を create の前に確かめる（歩5） |
| AttemptRecord なしの Applied | ApplyRecord が AttemptRecord を必ず材料に持つ。ApplyAttempt を経ない Applied は値として作れない |
| 適用が要る業務ルールなのに、適用を飛ばした完了 | Confirmed → Closed の道は、業務ルールが「適用は要らない」と決めているときだけ通る。close の門が業務ルールを読んで拒む（型では殺せないのでチェック） |
| 二度出る Irreversible | Apply は二相——Attempt だけ残して落ちたら、再実行は型に無く settle_attempt（Human）しか無い |
| SensitivityMark の付いた Source を指す Briefing を、Sensitivity 可でない者が take | take の呼べる者の制約。型で殺せない分は dispatch と take の Check で（壊すと赤くなるまで検証） |

---

- 型で殺せない2つ（dispatch の Check・Origin の Reconciliation）は **Check** として実装し、「壊すと赤くなる」まで検証する（I6）
