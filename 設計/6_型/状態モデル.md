# Ichiza（一座）— 状態モデル

**版**: v2.2（2026-08-21。v2.2: 適用が要らないタスクの道を遷移表に。v2.1: v2.1: 遷移表に執行者を付けた——required_events を Ledger の put がチェックする）
**状態**: **有効になった**（2026-08-21、人が有効化した）

Job の一生を、**その State でしか持てないものをその State だけが持つ**型に写す。記法——`|` は「どれか1つ」、`&` は「合わせ持つ」、`{ }` はその State が必ず持つもの。**ここに書いた名前が、そのまま domain/job.py の名前**（読みかた 掟9。日本語の語は用語集と docstring で引く）。「気をつける」ではなく「書けなくする」——pydantic は実行時にも弾くので、これは動いている最中まで効く。

## 1. Job の型

```
Job = Core & State

Core = { job_id, Origin, board_id,
         時刻の対（ready_at, deadline）, Budget, parent_job_id（ChildJob のみ） }
       ← Definition への参照は Core には無い。Origin（FromDefinition）と
         Briefing（definition_ref）が持つ——二重に持たない

Origin = FromDefinition { definition_name, version, period }
       | FromInstruction { utterance_id }
       | FromParent { parent_job_id }

State =
      Created                            … まだ dispatch されていない
    | Ready        { Briefing }          … 解決済みの Briefing を必ず持つ
    | Running      { Briefing, Lease, retries_left }
    | AwaitingAnswer { Briefing, question, addressee_id }
    | Verifying    { Briefing, artifact_ref }
    | Checkpoint   { artifact_ref, position, assignee_id }
    | Confirmed    { artifact_ref, approval? }     … Checkpoint の無い Job では approval 無し
    | ApplyAttempt { artifact_ref, attempt, approval? }
    | Applied      { artifact_ref, record }
    | Closed  = ClosedWithEvidence  { evidence_ref }
              | ClosedBySelfReport  { recheck_deadline }
    | Failure = EnvironmentFailure  { retries_left, return_to }
              | ContentFailure      { reason }   … Human へ。Budget 超えもここ

ApplyRecord =
      ReversibleApply   { actor, at, attempt: AttemptRecord }
    | IrreversibleApply { actor, at, attempt, approval: ApprovalRecord }
      ← Checkpoint の通過と「先に試みた」ことが、どちらも型の材料

CheckResult  = Passed | Blocked  { reason }
ReviewResult = Passed | Returned { reason }   … 別の型。混ざらない
```

## 2. 遷移（操作の型——誰が呼べるか込み）

この表は `required_events`（domain）としてコードに写り、**Ledger の put が執行する**——表に無い移りは IllegalTransition、必須の Event の欠けは MissingEvent。遷移表の執行者は帳簿の書き込み。

| 操作 | 遷移 | 呼べる者 |
|---|---|---|
| `create` | → Created | Manager・Reception・親の Worker |
| `dispatch` | Created → Ready | Manager（Briefing の解決と Gate の Check つき） |
| `take` | Ready → Running | Worker・Human（照合済みのみ。**SensitivityMark の付いた Source を指す Briefing は、Sensitivity 可の CapabilityDeclaration がある者だけ**） |
| `release`／`expire` | Running → Ready | Worker（理由つき）／patrol |
| `submit` | Running → Verifying | Lease の holder |
| `inquire` | Running → AwaitingAnswer | Lease の holder（問いつき） |
| `answer` | AwaitingAnswer → Running | **宛先の Human だけ**。答えは Utterance として落ち、Evidence に紐づく |
| `Blocked`・`Returned` | Verifying → Ready | Check／Review（理由が Briefing に足される） |
| `pass_verification` | Verifying → Checkpoint（位置が Definition にあるとき）／Confirmed（無いとき） | Check・Review |
| `approve` | Checkpoint → Confirmed | **assignee_id の本人だけ**（型の引数が担当） |
| `attempt_apply` | Confirmed → ApplyAttempt（**先に Attempt を記してから**外に出す） | Definition が決めた主体 |
| `record_outcome` | ApplyAttempt → Applied | 実行した主体 |
| `settle_attempt` | ApplyAttempt → Applied／Confirmed | **Human だけ**。再開で見つかった Attempt は勝手にやり直さず、外を確かめてから記す |
| `close` | Applied → Closed | Manager の confirm（Evidence の照合） |
| `close` | **Confirmed → Closed**（業務ルールが「適用は要らない」と決めているとき） | Manager の confirm。**外に出るものが無いタスクの道**——効かない適用を通さない |
| `crash` | どこからでも → Failure | — |
| `retry` | EnvironmentFailure（残りあり） → return_to の State | Manager |

## 3. 未決#8への結論

- **Progress の刻み方** — Progress は Event。何をどの間隔で刻むかは Definition が決める（ポリシー）。途絶の判定は patrol
- **Budget の形** — 量と時間の対。超えは **ContentFailure** として Human へ（自動で使い続けない）
- **Lease の返し方** — Running → Ready。理由が Event に残り、CapabilityDeclaration との Discrepancy の材料になる
- **差し戻しの行き先** — Ready に戻る。理由への参照が Briefing に足される（詰め直し）
