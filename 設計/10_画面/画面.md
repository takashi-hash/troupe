## 0. 決定

- **ネイティブ GUI（PySide6／Qt）に決定**（2026-08-21。前の「サーバ側で描く」を名指しで覆す）。理由: ①ブラウザを要らなくし、ローカル描画で**サクサク** ②「言語を割らない」条件は Python の GUI なのでそのまま満たす ③常駐サーバが1プロセス減る。PySide6 は Generic＝買い物（ui の足場）
- 更新は帳簿を**短い周期で読み直す**（Event の seq を見て変化があれば再描画）。**画面は常に導出**——落ちても開き直せば同じものが出る、はそのまま
- **効かない入口を出さない**: Chat・「承認」ボタンは、その仕組みが実装されるまでサイドバーに出さない（教訓5）
- **読める大きさで作る**（2026-08-21、実地で見て決定）: 窓は 1440×950（最小 1100×720）、本文 15px、見出し 34px、カードの余白は広く。小さく詰めない
- **画面の語は一般的な業務システムの語**（2026-08-21、実地で見て決定）: 承認待ち・未着手・実行中・完了・エラー・期限……のように、初めて見た人が説明なしで読める語だけを使う。**画面だけ言い換えるのではなく、用語集ごと改名した**（掟10 の手順そのもの——用語集 v4.0）。識別子（Job・Checkpoint・approve）は1つも変えていないので、コードと設計は無傷

## 1. 作り（未決#4への結論）

**サイドバー＋ペイン。**

- サイドバー: 6つの入口——今日／予定／履歴／検索／チャット＋（文脈があるとき）詳細。**要対応の件数バッジは「今日」にだけ**付く（Alert の出口は1本）
- ペイン: 選んだ枚を1枚だけ表示。枚をまたぐ遷移は「Job を1つ選ぶ→詳細」だけ
- 書ける場所は**チャットの入力欄と、「今日」の「承認」「回答」ボタンだけ**。他は全部読むだけ
  - 「承認」→ approve（担当の本人にだけ出る）
  - 「回答」→ answer（宛先の本人にだけ出る）
  - どちらも押した事実が Event に残る（押し間違いは Confirmed が最後の戻れる地点）
  - **断られたら、断られたと出す**（例: 担当ではない・もう誰かが承認した）。
    押して何も起きないのが一番わるい。**操作の失敗はエラーではない**——タスクの状態は変わらないので、
    タスクの一生に傷をつけず、画面にだけ理由を出す（帳簿には試みが残る）

## 2. 導出（枚の中身はどこから来るか）

- どの枚も**純粋な導出関数**: `(Aggregate たち, Event 列) → 枚の中身`。ui はこれを描くだけ
- 判定（何が赤か・何を載せないか）は **surface の1箇所**から読む——画面側で判定しない（Alert の出口は1本）。
  **今日の枚は Alert しか受け取らない**——タスクを渡さないので、判定しようにも材料が無い（型が掟の執行者）。
  2026-08-21 まではこれが逆で、画面が自分で判定していた。そのあいだに掟から2つずれた——
  環境エラーを今日に出していた（狼少年）／自己申告の確かめ期限を出していなかった（抜け）
- **エラーの見せ分け**（狼少年を作らない）:
  - **EnvironmentFailure は「今日」に出さない**——再試行中だから。人が今できることが無い
  - **ContentFailure は出す**——再試行が尽きた・成果の質の問題。人の判断が要る
  - **どちらも履歴には残す**——後から「何度落ちたか」を辿れる（I5）
- Outlook の「予定」は Definition×Calendar から導出（Job はまだ無い。選ぶと Definition の該当 Version を見せる）
- **domain の型を画面に直接返さない**——導出関数は画面用の値（表示文字列と ID）だけを返す

## 3. Chat（画面名: チャット）

- 入力 → UtteranceLogged → Reception が仕分け（非同期）→ 返答・作成済み Job への案内が、次の読み直しで画面に出る
- Agent → Human の口もここに出る: Inquiry（回答待ちの問い）・ProposalCreated（enact 待ち）・判断の材料
- 「enact して」「却下」もチャットで言える（Reception が写す。effect の Event が残る）

## 3.5 検索（画面名: 検索）

**なぜ要るか**: 「今日」は今日のぶん、「予定」は作成済みのぶん、「履歴」は近ごろのぶんしか見せない。
**完了したタスクに手が届く経路が無かった**——帳簿には証拠も経緯も全部あるのに、画面の側で切れていた（I5 の穴）。

- **対象は、完了も含めたすべてのタスク**（`all_jobs`）。ここが他の枚との違い
- **絞り込みは「予定」と「履歴」にも付ける**。検索と同じキーを使う——枚ごとに別の絞り方を作らない
- **「今日」には絞り込みを付けない**——唯一の押しつけなので、絞れるようにすると
  「今日やることだけ」という意味が消える
- 検索と絞り込みの違いは**対象の広さだけ**: 絞り込みはその枚が見せているもの（予定＝作成済み、
  履歴＝近ごろ）を狭める。検索は**完了も含めた全部**から引く
- 検索は**読むだけ**。ここから何かが起きることはない（詳細へ辿るだけ）

### 検索のキー — モデルの欄と1対1

**思いつきでキーを足さない。** 足したくなったら、それはモデルに欄が足りない合図。

| キー | モデルのどの欄か | 選択肢の導き方 |
|---|---|---|
| キーワード | 業務ルールの名（作成元）・成果物の中身・エラーの理由 | 自由入力 |
| 状態 | タスクの状態（State） | **状態モデルから導く**（手書きの一覧にしない） |
| 業務ルール | 作成元（FromDefinition.definition_name） | **帳簿のタスクから導く** |
| 担当 | 承認待ちの assignee_id ／ 札の holder | **帳簿のタスクから導く** |
| 期限 | 芯の deadline | 日付の範囲 |

新しい状態や業務ルールが増えたら、**選択肢が勝手に追いつく**（名指しの一覧より、宣言から導く）。

判定（合うか）は**仕様**なのでドメインに置く（`domain/search.py`）——画面は条件を渡して描くだけ。

**まだ効かせていないこと**: 機微による見え方の制限。いまは人が1人なので掛けていない
（人が増えたら、未決#9「担当の引き継ぎ」と一緒に決める）。

## 4. 画面の言葉

- 術語のラベルは**用語集 §10 の語だけ**。§10 に無い語（Lease・Core・Fingerprint…）は画面に出さない
- **画面の語 lint**: `tests/ui_words_lint.py` が STATE_LABELS の値・画面の名前・操作の表示・**絞り込みの見出しと既定の選択肢**を §10 と突き合わせる——掟10 の執行者。§10 が §2〜§8 の部分集合であることも見る（別名を作っていないこと）。出来事の名前と説明文は語ではなく文なので見ない
- 中身は現場の言葉（題材ごと——運転ならリポジトリや依存）で、Constitution から来る——ラベルと混ざらない

## 5. テストと評価（この層の流儀）

| 何を | どう |
|---|---|
| 導出関数 | **例が仕様**: この Event 列と Aggregate なら、「今日」にこれが載る／載らない。「毎回同じ Alert は載らない」「先の予定は載らない」も1行1テスト |
| 狼少年のチェック | 同じ Alert を2度並べたら赤（surface の冪等が画面まで通っていること）。**環境エラーが今日に出たら赤**——再試行の最中で、人が今できることが無い |
| 判定の置き場 | 今日の枚が Alert 以外を受け取ったら赤（`tests/rings_lint.py`）——材料が届けば画面はまた判定を始める |
| ボタンの出しわけ | 「承認」が担当以外に出ないこと。出しわけ条件を消して赤 |
| 画面の語 lint | §10 に無い表示を混ぜて赤。戻して緑（2026-08-21 に確認済み。絞り込みの見出しでも確認） |
| 絞り込み | **例が仕様**: 業務ルールで絞ると1件だけ残る／状態で絞ると予定（まだ作成されていないもの）は出ない／履歴は合うタスクの出来事だけ残る |
| 描画の薄い層 | 各枚の smoke（描けて、術語ラベルが§10 内）だけ。凝った見た目のテストはしない——**厚みは導出に、薄さは描画に** |

評価軸: MorningSheet が読まれ続けているか（I1〜I8 の見え方の出口）。「読まれなくなった Alert」は実測で見つけて消す（狼少年を作らない・消す前に測る）。
