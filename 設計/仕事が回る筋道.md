# Ichiza（一座）— 仕事が回る筋道

**版**: v2.0（2026-08-22）
**役目**: 誰が何を起こすか。判断はどこにあるか。何を出し入れするか。**ここで閉じる。**

[仕事とは何か](仕事とは何か.md)が「何を持つか」、この1枚が「どう動くか」。

---

## 1. 誰が始めるか

**4種類。分けるのは、公理の境目を一覧から読めるようにするため。**
人の分だけが判断で、AI の分も時計の分も判断ではない。

### 人が始めるもの — **ここだけが判断**

| 操作 | 識別子 | 何をするか |
|---|---|---|
| 頼む | `request` | 依頼を読んで仕事を作る |
| 承認する | `approve` | 差し出した承認を渡す。**受け持ちの人だけ**（I6） |
| 差し戻す | `send_back` | 理由をつけて着手できるへ戻す |
| 答える | `answer` | 質問に答える。**答えは根拠にならない**——根拠は源から取る |
| 版を積む | `add_version` | **題材のデータを初期値として読み、人が上書きした値**で版を積む |
| 有効にする | `activate` | その版で仕事を生してよいと決める |
| 止める | `deactivate` | その版で仕事を生すのを**やめる**と決める。有効な版の番号が空に戻る——**版の列はそのまま**（積むだけ） |
| 定期訪問を決める | `add_pattern` | 患者と調整した定期訪問の取り決め（曜日・**週の間隔**・担当）を診療録に載せる。**取り決めこそが判断**——ここから先の展開は機械 |
| 定期訪問を終える | `end_pattern` | 取り決めに終わりの日を入れ、**その取り決め由来のまだ来ていない予定を中止に倒す**（判断の帳簿づけ——展開の巻き戻し）。**列は消さない** |
| 署名して訪問を終える | `sign_note` | 下書きを下敷きに人が書き上げた S/O/A/P を**署名済みの記録**として診療録に積み、訪問を実施済みへ倒し、使った下書きに使用の印を入れる（**診療録の1トランザクション**）。**この記録を事実とするのが判断**——帳簿には書かない（カルテの正本は診療録） |
| 訪問を1回だけ休む | `cancel_visit` | その1回の予定だけを理由つきで中止に倒す。取り決めは生きたまま——**この回は行かないと患者と決めたのが判断**（`end_pattern` の単発版。実施済みは倒せない） |
| 打ち切る | `abandon` | 追えなくなった仕事を理由つきで終点へ |

### AI が始めるもの

**引き金は AI 自身。常駐して、2つを見に来る。**

1. **着手できる**仕事——取って進める
2. **人の手が要る仕事**（**上限に触れた・やり直しが尽きた**・確かめ期日が来た・**根拠なしで終わった**）——**見立てを書く**

2つ目が無いと、**落ちた仕事に見立てが付かない**。時計に「AI を起こす」を置かない
——**自律とは、呼ばれずに来ること**。常駐する仕組みは汎用（買う）。

| 操作 | 識別子 | 何をするか | 判断ではない理由 |
|---|---|---|---|
| 着手する | `start` | 着手できる仕事を取り実行中へ——**材料（答えのある質問など）を揃えるのは `consult`** | 取れるかは型が決める |
| **LLM に問う** | `consult` | 源を読み（**読めなければ `fail` へ**）、LLM に渡し、**`Reply` と使った回数・秒**を受け取る。使った量を積み、**仕様に振り分けさせて**、質問・成果・見立てのどれかを返す | **振り分けるのは仕様**。この操作は運ぶだけ |
| 尋ねる | `ask` | 質問を積んで答え待ちへ | **判断は求めない**。材料の不足だけ |
| 出す | `submit` | 成果を積む。**源をもう一度読んで引用が取れれば**根拠も積む。取れなければ根拠なしで出す | 合否は決めない |
| 落ちる | `fail` | 落ちた中身を残す | 何が起きたかを残すだけ |
| 使い切る | `exhaust` | 使用上限に達したことを残して失敗したへ | 数が上限に触れただけ |
| 手放す | `release` | 担当を外して着手できるへ | やめる判断ではない |
| 見立てを書く | `assess` | 読んだ結果と理由を積む。**担当でなくても書ける**（I13 の例外）——落ちた仕事・終わった仕事こそ見立てが要る。**状態を変えない**（`hand_over` は見立てを書いたうえで失敗したへ落とす） | **事実の報告と案。決めるのは人** |
| 人へ回す | `hand_over` | もう自力で進めないと**仕様が言ったとき**、見立てを書いて人の判断を待つ。**落ちた中身には見立ての本文をそのまま置く** | **進めないという事実の報告**。どうするかは人が決める |
| 使った量を積む | `spend` | LLM を呼んだぶんの回数と秒を足す。**`consult` の中で呼ばれる** | 数えるだけ。上限で止まる（I14） |
| 巡回する | `patrol` | 人の手が要る仕事を見に行き、見立てを書く（**I15 の執行者**）。実行中で行き詰まったものは人へ回す | 書くべきかは仕様が決める |

### 画面が始めるもの

**人が画面を開いたときだけ走る。帳簿に書かない。**

| 操作 | 識別子 | 何をするか | 判断ではない理由 |
|---|---|---|---|
| 今日の分を集める | `gather_today` | いまこの人の目と判断が要るものを集める | **判定するのは仕様**。集めて渡すだけ |
| 詳細を集める | `gather_detail` | 1件の全部（出来事・問答・見立て）を集める | 同上 |
| 予定を集める | `gather_schedule` | 業務ルールの一覧と次の対象期間・未作成のもの、**作られた仕事の列（終点以外）**を集める | 同上。未作成の判定は `reconcile` |
| 履歴を集める | `gather_history` | 出来事の列を新しい順に、**どの仕事かの見出しを添えて** | 読むだけ。書かない |
| 検索する | `gather_search` | 絞り込みの条件で仕事の行を引く——**終わったものも含めて** | 同上。**状態の語→識別子の橋はここ** |
| 道順を集める | `gather_route` | その日の担当ごとに、予定の訪問を拠点から近い順に並べる | 距離の比べだけ。並べて渡す |
| 訪問を集める | `gather_visit` | 1訪問の当日入力の材料（患者の要約・未使用の下書き・署名済みの記録・担当の名簿）を写す | 読むだけ。**中の語に翻訳しない** |
| 定期訪問を集める | `gather_patterns` | 取り決めの一覧を写す | 読むだけ。書かない |
| 患者を集める | `gather_patients` | 診療録（**よそのコンテキスト**）の患者の一覧を写す | 読むだけ。**中の語に翻訳しない** |
| 患者の詳細を集める | `gather_patient` | 1人のカルテ抽出（処方・指示書・予定・出来事・記録）を写す | 同上 |

**時計に置かない。** 置くと結果の置き場が要り、**保存しない判定を保存する**ことになる。
画面は常に導出——開いた瞬間の帳簿を見る。

### 時計が始めるもの

**誰も呼ばなくても回る。何度回しても同じ結果になる**——`confirm` だけは源を読むので例外。

| 操作 | 識別子 | 何をするか | 何度回しても同じ理由 |
|---|---|---|---|
| 作る | `create` | 有効な版といまから、まだ無い仕事を作る | 作成元が一意（I3） |
| 配る | `hand_out` | 作られた仕事を着手できるへ | 既に配ったものは触らない |
| 時間切れを戻す | `return_timed_out` | 期限の切れた担当を外す | 切れていないものは触らない |
| 検査を回す | `run_check` | 成果の中身を受け入れ基準で見る。**通ったら担当を受け持ちの人へ移す** | **同じ成果なら、いつ回しても同じ結果**（`{対象期間}` は写すときに開かれ済み） |
| 失敗を仕分ける | `sort_failures` | **やり直した回数が上限に届かず、使った量が使用上限に届かなければ**やり直す。どちらか届けば残す | 比べるだけ。**4つとも仕事が持つ**——Store に尋ねない |
| 確かめる | `confirm` | **根拠の在りかが空でなければ**終わる。空なら源を読み直し、引用が取れれば積んで終わる。取れなければ**確かめ期日を先へ送る** | 積まれた根拠は必ず揃っている（`Evidence` の義務）。**源を読むのでここだけ結果が変わりうる** |
| 期日切れを刻む | `mark_overdue` | 期日を越えた仕事に一度だけ印を残す | 日付の比べだけ |
| 突き合わせる | `audit` | 有効な版に対して、いまの対象期間の仕事が在るかを数え合わせる（**I8 の周期で回る突合**） | **読むだけ**。書かない |
| 予定を組む | `plan_visits` | 有効な定期訪問の取り決めから、先の予定をまだ無ければ診療録に作る。**取り決めの展開は帳簿づけ**——`create` が版×暦から仕事を作るのと同型 | 作成元が一意（取り決め×日付——診療録の一意の鍵） |
| 下書きを配達する | `deliver_drafts` | 承認の済んだカルテの下書きを診療録へ **draft としてだけ**置く。置けたら **`DraftDelivered` を刻む**——配達は帳簿に残る事実（F4） | 承認は済んでいる。運ぶだけ——**印の無いものだけ運ぶ**（診療録の一意の鍵は二重の守り） |

### 人から受け取る値

画面から app へ渡るのは**文字だけ**——人が書いた中身を app が値に組む。**受け取る欄が無いと、押しても値が作れない**。

| 操作 | 人が書くもの |
|---|---|
| 答える | 答えの本文 |
| 差し戻す | 理由 |
| 打ち切る | 理由 |
| 頼む | 頼む中身・源・必ず含む語（**この3つは人が書く**）。残りは書かなければ既定——**やること=頼む中身・受け持ち=頼んだ人**・周期=週・日数=3・使用上限=20回600秒・やり直し=2 |
| 版を積む | やること・源・受け入れ基準・周期・日数・使用上限・受け持ちの人・やり直しの上限 |

### 決まり

- **業務の規則を持たない。** `if` で業務を判断したくなったら、集約かドメインサービスへ
- **ひと仕事＝ひとトランザクション。** 境界を握るのはここ
- **積む者を必ず書く。** 読む者しか居ない置き場は、中身が永久に0件になる
- **数を動かす者を必ず書く。** 増やす者が居ない数は永久に0のまま

**数の正本はこの節。** どれかが極端に増えたら判断が寄っている合図——人が増えれば手間が増えすぎ、AI が増えれば決めすぎ、時計が増えれば自動で動きすぎ、画面が増えれば開くたびに重くなる。

## 2. 判断のありか — ドメインサービスと仕様

**どちらも domain。帳簿を開かない・書かない。材料を受け取って答えを返すだけ。**
書くのはアプリケーションサービス。

### ドメインサービス — どの集約のものでもない業務の判断

**見分けかた**: 引数に集約が2つ以上出てきて、返り値がそのどれでもない。

| 何を判断するか | 識別子 | 材料 | なぜ集約に入らないか |
|---|---|---|---|
| いま何を作るべきか | `reconcile` | 有効な版の（識別子・番号・周期）の列 ＋ 既にある作成元の鍵の列 ＋ **いま** | 業務ルールと仕事の両方をまたぐ |
| いま**この人の**目と判断が要る仕事はどれか | `judge_today` | 今日の材料の集まり ＋ **それぞれの押せることの列** ＋ **いま** | どの仕事のものでもない |
　　└ **呼ぶ順は 今日の材料 → 押せること → judge_today。** 押せることが空の行は返さない |

**`reconcile` が対象期間も決める。** 周期といまから `Period` を出す——
これは業務の判断なので app に置けない。

### 仕様 — 白黒つける述語

| 何を問うか | 材料 | 答え |
|---|---|---|
| 成果が受け入れ基準を満たすか | 成果の中身 ＋ 受け入れ基準の**必ず含む語** | 通る／止まる＋理由。**文字の照合だけ**——だから何度でも同じ結果になる |
| 差し出された承認が受け持ちの人のものか | 仕事 ＋ **差し出された承認** | 真偽（I6） |
| いまこの仕事に**この人が**押せる操作はどれか | **今日の材料**（**domain の値**。欄の正本は[人に見えるもの §2](人に見えるもの.md)）＋ **見ている人** ＋ **いま** | 操作の列。**遷移表に無い操作は返さない** |
| **`Reply` をどれに振り分けるか** | **`Reply`（印と本文）** ＋ 受け入れ基準の**必ず含む語** | 印が質問なら**質問**へ。印が成果で、本文が必ず含む語を**すべて含めば成果**へ。**含まなければ見立て**へ——**名乗りを検めるのがここ**。印がどちらでもないなら**見立て**へ |
| **もう自力では進めないか** | 前に出した成果の中身 ＋ 止まった理由の列 ＋ やり直した回数 | 真なら `hand_over`（実行中から） |
| いまこの業務ルールに**人が押せる操作**はどれか | 有効な版の有無 | 版を積む・有効にする はいつでも。**止めるは有効な版があるときだけ** |
| **いまこの仕事に見立てを書くべきか** | これまでの見立て ＋ 落ちた中身と止まった理由の列 ＋ **使った量と使用上限** ＋ **やり直した回数とやり直しの上限** | 真偽（F6——**同じ見立てを二度書かない**）。**上限に触れた・やり直しが尽きたときは必ず真**（I15） |

**LLM の応答の振り分けは業務の判断**（I16）。adapters は形を整えるだけ。
使った回数と秒は翻訳の対象ではない——`LlmPort` が応答とは別に返す。

### 見分けの物差し

| 形 | 何か | 置き場 |
|---|---|---|
| `X → X` | 集約の操作 | その集約の隣 |
| `部品 → 真偽` | 仕様 | domain |
| `いくつかの集約 → 判定` | ドメインサービス | domain |
| `帳簿 → 書き込み` | アプリケーションサービス | app |

**ドメインサービスは逃げ場になる。** 迷ったら**「その操作の主語は誰か」を先に問う**。
主語になれる集約があるなら、そちらの操作にする。

### ポリシー

**版が「何をすべきか」をデータとして持ち、人が有効にする。コードにしない。**

| 版が持つもの | 何を生むか |
|---|---|
| やること `Instruction` | **AI が何をするか** |
| 源 `Source` | AI がどこを読むか |
| 受け入れ基準 | 検査が何を見るか |
| 周期 | いつ・どの対象期間の仕事を作るか |
| 終えるまでの日数 | 期日 |
| 使用上限 | どこで止まるか |
| 受け持ちの人 | 誰が承認し、誰が質問を受けるか |

**版に何を書いても不変条件は破れない。**

## 3. ファクトリ — 生成と再構成

**不変条件を満たしたものだけが生まれることを保証するため。** new を隠すためではない。

### 仕事の生成

| 持ちもの | 何から決まるか |
|---|---|
| `JobId` | **立てた者が振る**（採番はファクトリの外） |
| `Origin` | 業務ルール発なら `RuleName`＋版の番号＋`Period`、依頼発なら依頼の識別子 |
| 生まれた版 | 生成の時点で固定 |
| 版から写すもの | **[仕事とは何か §4](仕事とは何か.md)の共通の持ちものを、すべて写す**（正本はそちら） |
| `DueDate` | **起点の時刻 ＋ 版の日数**（依頼発は依頼の時刻、業務ルール発は作られた時刻） |
| `Spent` | `Spent(0, 0)` |
| 初期状態 | 作られた |

**版そのものは渡さない。** `Rule` 集約が「写すものの束」（共通の持ちもの＋終えるまでの日数）を返し、日数は `DueDate` になって消える。

### 生成と再構成はまったく別

| | 生成 | 再構成 |
|---|---|---|
| いつ | 新しい1件が生まれるとき | 帳簿から読み戻すとき |
| 業務の規則 | **効かせる**（上の表が規則） | **効かせてはいけない** |

**再構成に今の規則を効かせると、きのう書いた行をきょうの規則で弾く。** 効かせるのは型の形だけ——合わなければ「読めない、入れ直せ」と名乗って止まる。**古い帳簿は捨ててよい**——注入し直せば戻る。だめなのは黙って壊れること。

## 4. interface（**正本**）

**接尾辞が役割を言う。この表と §1 の4表は突合が守る**——名は識別子↔ファイル、宣言は場所、要求者は import と照合。

| interface | 接尾辞 | 何を出し入れするか | 宣言 | 実装 | 要求者 |
|---|---|---|---|---|---|
| `JobRepository` | Repository | 仕事の集約ルートを鍵で1件 | domain | adapters | 集約: 仕事（I1）／すべての書き込み |
| `RuleRepository` | Repository | 業務ルールの集約ルートを鍵で1件 | domain | adapters | `create`・`add_version`・`activate`・`deactivate`（**`run_check` は仕事が写した基準を見る**） |
| `RuleReader` | Reader | 業務ルールの一覧（名・版の番号・有効な版・やること——**やることは有効な版のもの、無ければ最新**） | **app** | adapters | `gather_schedule` |
| `ResultStore` | Store | 成果を積む | domain | adapters | 積む: `submit` ／ 読む: `run_check`（**画面の読みは Reader が担う——運び手は1本**） |
| `EvidenceStore` | Store | 根拠を積む | domain | adapters | 積む: `submit`・`confirm` ／ 読む: `confirm`（**同上**） |
| `QuestionStore` | Store | 質問と回答を積む | domain | adapters | 積む: `ask`・`answer` ／ **読みは `WorkReader`・`TodayReader` が担う**（同上） |
| `AssessmentStore` | Store | 見立てを積む | domain | adapters | 積む: `assess` ／ **読みは `WorkReader`・`TodayReader` が担う**（同上） |
| `ClockPort` | Port | いまの時刻を出す | **app** | adapters | **人・AI・時計のすべて**と `gather_today`・`gather_detail`・`gather_schedule`（履歴・検索に「いま」は要らない） |
| `IdPort` | Port | 新しい識別子を振る | **app** | adapters | `request`・`create` |
| `LlmPort` | Port | LLM に渡し、**`Reply`（印つき）と、使った回数・秒**を受け取る。**巡回には状況を読ませて見立ての本文をもらう**——見立てが無いと AI は数字しか出せない。**見立ての一呼びは使用上限に数えない**（安全弁は仕事を進める暴走を止めるもの。見立ての暴走は F6 が止める） | **app** | adapters | `consult`・**巡回** |
| `SourcePort` | Port | 源から読む。**源の言葉を業務の語へ翻訳**（腐敗防止層＝ACL）。出口は**引用・読めなかった理由**の2つ——読めた中身は引用が兼ねる（**返す者の居ない出口は置かない**） | **app** | adapters | `consult`・`submit`・**`confirm`**（根拠の引用を取る） |

### 決まり

| 決まり | なぜ |
|---|---|
| **Store の「積む」は在りかを返す** | 在りかを別に振ると、振る者と積む者が2つになる |
| **Repository は集約ルートにつき1つ。返すのは集約ルートだけ** | 部品を外に出すと境界の外で書き換えられる |
| **Repository は鍵で1件。一覧と絞り込みは Reader** | 中心の interface に画面の都合が入り込まない |
| **Reader は書かない。Reader と Port の返す型は渡す先で決まる**——画面と LLM へは文字と ID、**domain の仕様へは domain の値**（`TodayReader`→今日の材料、`LlmPort`→`Reply`）。宣言が app でも返す型が domain なら**依存は内向き** | 判定の材料を app の型にすると、domain が app を見る |
| **Port は domain に現れない** | 外の道具は指せる不変条件を持たない |
| **要求者の欄が空の interface は置かない** | 誰も呼ばない宣言が、前回いちばん増えた |
| **積む者が空の Store は置かない** | 中身が永久に0件になる（根拠がそうなっていた） |
| **「まだ置かない」という節を作らない** | 置かない理由（「◯◯が一覧に無い」）は消えても気づけない。**実際に4本が理由の消えたまま残った** |

### 依存性逆転

domain が「出し入れできること」を型として宣言し、adapters が内向きに実装する。
**矢印の向きを変えるためだけの仕掛け。**

### 書き込みの門

**姿だけでは呼べない形にする。** 引数は「**新しい姿と、その理由のドメインイベントの列（空でない）**」の対1つ。
空の列がそもそも作れない——これが I1 の実物。列にするのは、1つの遷移で出来事が2つ残る道があるから
（頼む＝`JobRequested`＋`JobCreated`）。
**楽観ロックは口へ漏らさない**。返すのは「書けたか／書けなかったか」だけ。

## 5. ドメインイベント（**正本**）

**過去形。観察だけ。判断を含まない。積むだけ。**

**すべての出来事が「いつ・誰が」を持つ。** 誰が＝`Actor`（人・AI・時計）。
下の表は**それに足して残るもの**だけを書く——共通を書き分けると、どこかで落ちる。残るものの義務は値と同じ（空の理由・空の中身・0回の増加は残せない）。**太字（人が主語）は `by` の型が人**——突合が守る。

| 出来事 | 何が残るか | 識別子 |
|---|---|---|
| 仕事が頼まれた | 誰が・何を | `JobRequested` |
| 仕事が作られた | どの業務ルールの、どの版の、どの対象期間 | `JobCreated` |
| 仕事が配られた | — | `JobHandedOut` |
| 着手された | 誰が取ったか | `JobStarted` |
| 手放された | 誰が離したか | `JobReleased` |
| 時間切れで戻った | 誰の担当だったか | `JobTimedOut` |
| 成果が出された | 成果の在りか ＋ **根拠の在りか** | `ResultSubmitted` |
| 検査に通った | **誰へ担当が移ったか** | `CheckPassed` |
| 検査で止まった | 止めた理由 | `CheckStopped` |
| **承認された** | — | `Approved` |
| **差し戻された** | 誰が・理由 | `SentBack` |
| 終わった | 根拠の在りか、または確かめ期日 | `JobFinished` |
| 確かめ期日が先へ送られた | 新しい確かめ期日 | `RecheckDatePushed` |
| **打ち切られた** | 誰が・理由 | `JobAbandoned` |
| 期日を過ぎた | — | `DueDatePassed` |
| 下書きが配達された | —（どこへ置いたかは源が知っている） | `DraftDelivered` |
| 失敗した | 落ちた中身 | `JobFailed` |
| もう一度やった | 何度目か | `Retried` |
| 使った量が増えた | 増えた回数と秒 | `SpentIncreased` |
| 質問された | 何を | `QuestionAsked` |
| **答えられた** | 誰が・何と ＋ **誰の担当が外れたか** | `QuestionAnswered` |
| **見立てが書かれた** | 読んだ中身と、そう読んだ理由 | `AssessmentWritten` |
| 版が足された | どの版か | `RuleVersionAdded` |
| **業務ルールが有効になった** | 誰が・どの版か | `RuleActivated` |
| **業務ルールが止められた** | どの版を止めたか | `RuleDeactivated` |

**太字は人が主語。** ここが「判断は人間」の実物。
**見立ては AI が主語だが判断ではない**——事実の報告と案で、受けて決めるのは人。
