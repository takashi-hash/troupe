# Ichiza（一座）— 仕事が回る筋道

**版**: v2.0（2026-08-22）
**役目**: 誰が何を起こすか。判断はどこにあるか。何を出し入れするか。**ここで閉じる。**

[仕事とは何か](仕事とは何か.md)が「何を持つか」、この1枚が「どう動くか」。

---

## 1. 誰が始めるか

**4種類。分けるのは、公理の境目を一覧から読めるようにするため。**
人の分だけが判断で、AI の分も時計の分も判断ではない。

### 人が始めるもの — **ここだけが判断**

| 操作 | 識別子 | 何をするか |
|---|---|---|
| 頼む | `request` | 依頼を読んで仕事を作る |
| 承認する | `approve` | 差し出した承認を渡す。**受け持ちの人だけ**（I6） |
| 差し戻す | `send_back` | 理由をつけて着手できるへ戻す |
| 答える | `answer` | 質問に答える。**答えは根拠にならない**——根拠は源から取る |
| 版を積む | `add_version` | **題材のデータを初期値として読み、人が上書きした値**で版を積む |
| 有効にする | `activate` | その版で仕事を生してよいと決める |
| 打ち切る | `abandon` | 追えなくなった仕事を理由つきで終点へ |

### AI が始めるもの

**引き金は AI 自身。常駐して、2つを見に来る。**

1. **着手できる**仕事——取って進める
2. **人の手が要る仕事**（**上限に触れた・やり直しが尽きた**・確かめ期日が来た・**根拠なしで終わった**）——**見立てを書く**
   （**時計がまだ仕分ける仕事は拾わない**——拾うと `sort_failures` が1回で止まる）

2つ目が無いと、**落ちた仕事に見立てが付かない**。落ちた仕事こそ見立てが要る。
時計に「AI を起こす」を置かない——置くと AI が受け身になり、**自律とは呼ばれずに来ること**でなくなる。
常駐する仕組みは汎用（買う）。

| 操作 | 識別子 | 何をするか | 判断ではない理由 |
|---|---|---|---|
| 着手する | `start` | 着手できる仕事を取り、**やること・受け入れ基準・答えのある質問**を揃えて実行中へ | 取れるかは型が決める |
| **LLM に問う** | `consult` | 源を読み（**読めなければ `fail` へ**）、LLM に渡し、**`Reply` と使った回数・秒**を受け取る。使った量を積み、**仕様に振り分けさせて**、質問・成果・見立てのどれかを返す | **振り分けるのは仕様**。この操作は運ぶだけ |
| 尋ねる | `ask` | 質問を積んで答え待ちへ | **判断は求めない**。材料の不足だけ |
| 出す | `submit` | 成果を積む。**源をもう一度読んで引用が取れれば**根拠も積む。取れなければ根拠なしで出す | 合否は決めない |
| 落ちる | `fail` | 落ちた中身を残す | 何が起きたかを残すだけ |
| 使い切る | `exhaust` | 使用上限に達したことを残して失敗したへ | 数が上限に触れただけ |
| 手放す | `release` | 担当を外して着手できるへ | やめる判断ではない |
| 見立てを書く | `assess` | 読んだ結果と理由を積む。**担当でなくても書ける**（I13 の例外）——落ちた仕事・終わった仕事こそ見立てが要る。**状態を変えない**（実行中からは `hand_over`） | **事実の報告と案。決めるのは人** |
| 人へ回す | `hand_over` | もう自力で進めないと**仕様が言ったとき**、見立てを書いて人の判断を待つ | **進めないという事実の報告**。どうするかは人が決める |
| 使った量を積む | `spend` | LLM を呼んだぶんの回数と秒を足す。**`consult` の中で呼ばれる** | 数えるだけ。上限で止まる（I14） |

### 画面が始めるもの

**人が画面を開いたときだけ走る。帳簿に書かない。**

| 操作 | 識別子 | 何をするか | 判断ではない理由 |
|---|---|---|---|
| 今日の分を集める | `gather_today` | いまこの人の目と判断が要るものを集める | **判定するのは仕様**。集めて渡すだけ |

**時計に置かない。** 置くと結果の置き場が要り、**保存しない判定を保存する**ことになる。
画面は常に導出——開いた瞬間の帳簿を見る。

### 時計が始めるもの

**誰も呼ばなくても回る。全部、何度回しても同じ結果になる。**

| 操作 | 識別子 | 何をするか | 何度回しても同じ理由 |
|---|---|---|---|
| 作る | `create` | 有効な版といまから、まだ無い仕事を作る | 作成元が一意（I3） |
| 配る | `hand_out` | 作られた仕事を着手できるへ | 既に配ったものは触らない |
| 時間切れを戻す | `return_timed_out` | 期限の切れた担当を外す | 切れていないものは触らない |
| 検査を回す | `run_check` | 成果の中身を受け入れ基準で見る。**通ったら担当を受け持ちの人へ移す** | **同じ成果なら、いつ回しても同じ結果**（`{対象期間}` は写すときに開かれ済み） |
| 失敗を仕分ける | `sort_failures` | **やり直した回数が上限に届かず、使った量が使用上限に届かず、見立てが書かれていなければ**やり直す。どれか当たれば残す | 比べるだけ。4つとも仕事が持つ |
| 確かめる | `confirm` | **根拠の在りかが空でなければ**終わる。空なら源を読み直し、引用が取れれば積んで終わる。取れなければ確かめ期日を置いて終わる | 積まれた根拠は必ず揃っている（`Evidence` の義務） |
| 期日切れを刻む | `mark_overdue` | 期日を越えた仕事に一度だけ印を残す | 日付の比べだけ |


### 人から受け取る値

画面から app へ渡るのは**文字だけ**。`Answer`・`SendBack`・`Assessment`・`Request` の
中身は人が書く——**受け取る欄が無いと、押しても値が作れない**。

| 操作 | 人が書くもの |
|---|---|
| 答える | 答えの本文 |
| 差し戻す | 理由 |
| 打ち切る | 理由 |
| 頼む | 頼む中身 |
| 版を積む | やること・源・受け入れ基準・周期・日数・使用上限・受け持ちの人・やり直しの上限 |

### 決まり

- **業務の規則を持たない。** `if` で業務を判断したくなったら、集約かドメインサービスへ
- **ひと仕事＝ひとトランザクション。** 境界を握るのはここ
- **積む者を必ず書く。** 読む者しか居ない置き場は、中身が永久に0件になる
- **数を動かす者を必ず書く。** 増やす者が居ない数は永久に0のまま

**数の正本はこの節。** どれかが極端に増えたら判断が寄っている合図——人が増えれば手間が増えすぎ、AI が増えれば決めすぎ、時計が増えれば自動で動きすぎ、画面が増えれば開くたびに重くなる。

## 2. 判断のありか — ドメインサービスと仕様

**どちらも domain。帳簿を開かない・書かない。材料を受け取って答えを返すだけ。**
書くのはアプリケーションサービス。

### ドメインサービス — どの集約のものでもない業務の判断

**見分けかた**: 引数に集約が2つ以上出てきて、返り値がそのどれでもない。

| 何を判断するか | 識別子 | 材料 | なぜ集約に入らないか |
|---|---|---|---|
| いま何を作るべきか | `reconcile` | 有効な版の識別子と番号の列 ＋ 既にある作成元の鍵の列 ＋ 周期 ＋ **いま** | 業務ルールと仕事の両方をまたぐ |
| いま**この人の**目と判断が要る仕事はどれか | `judge_today` | 今日の材料の集まり ＋ **それぞれの押せることの列** ＋ **いま** | どの仕事のものでもない |
　　└ **呼ぶ順は 今日の材料 → 押せること → judge_today。** 押せることが空の行は返さない |

**`reconcile` が対象期間も決める。** 周期といまから `Period` を出す——
これは業務の判断なので app に置けない。

### 仕様 — 白黒つける述語

| 何を問うか | 材料 | 答え |
|---|---|---|
| 成果が受け入れ基準を満たすか | 成果の中身 ＋ 受け入れ基準の**必ず含む語** | 通る／止まる＋理由。**文字の照合だけ**——だから何度でも同じ結果になる |
| 差し出された承認が受け持ちの人のものか | 仕事 ＋ **差し出された承認** | 真偽（I6） |
| いまこの仕事に**この人が**押せる操作はどれか | **今日の材料**（**domain の値**。欄の正本は[人に見えるもの §2](人に見えるもの.md)）＋ **見ている人** ＋ **いま** | 操作の列。**遷移表に無い操作は返さない** |
| **`Reply` をどれに振り分けるか** | **`Reply`（印と本文）** ＋ 受け入れ基準の**必ず含む語** | 印が質問なら**質問**へ。印が成果で、本文が必ず含む語を**すべて含めば成果**へ。**含まなければ見立て**へ——**名乗りを検めるのがここ**。印がどちらでもないなら**見立て**へ |
| **もう自力では進めないか** | 前に出した成果の中身 ＋ 止まった理由の列 ＋ やり直した回数 | 真なら `hand_over`（実行中から） |
| **いまこの仕事に見立てを書くべきか** | これまでの見立て ＋ 落ちた中身と止まった理由の列 ＋ **使った量と使用上限** ＋ **やり直した回数とやり直しの上限** | 真偽（F6——**同じ見立てを二度書かない**）。**上限に触れた・やり直しが尽きたときは必ず真**（I15） |

**LLM の応答の振り分けは業務の判断**（I16）。adapters は形を整えるだけ。
使った回数と秒は翻訳の対象ではない——`LlmPort` が応答とは別に返す。

### 見分けの物差し

| 形 | 何か | 置き場 |
|---|---|---|
| `X → X` | 集約の操作 | その集約の隣 |
| `部品 → 真偽` | 仕様 | domain |
| `いくつかの集約 → 判定` | ドメインサービス | domain |
| `帳簿 → 書き込み` | アプリケーションサービス | app |

**ドメインサービスは逃げ場になる。** 迷ったら**「その操作の主語は誰か」を先に問う**。
主語になれる集約があるなら、そちらの操作にする。

### ポリシー

**版が「何をすべきか」をデータとして持ち、人が有効にする。コードにしない。**

| 版が持つもの | 何を生むか |
|---|---|
| やること `Instruction` | **AI が何をするか** |
| 源 `Source` | AI がどこを読むか |
| 受け入れ基準 | 検査が何を見るか |
| 周期 | いつ・どの対象期間の仕事を作るか |
| 終えるまでの日数 | 期日 |
| 使用上限 | どこで止まるか |
| 受け持ちの人 | 誰が承認し、誰が質問を受けるか |

**版に何を書いても不変条件は破れない。**

## 3. ファクトリ — 生成と再構成

**不変条件を満たしたものだけが生まれることを保証するため。** new を隠すためではない。

### 仕事の生成

| 持ちもの | 何から決まるか |
|---|---|
| `JobId` | **立てた者が振る**（採番はファクトリの外） |
| `Origin` | 業務ルール発なら `RuleName`＋版の番号＋`Period`、依頼発なら依頼の識別子 |
| 生まれた版 | 生成の時点で固定 |
| 版から写すもの | **[仕事とは何か §4](仕事とは何か.md)の共通の持ちものを、すべて写す**（正本はそちら） |
| `DueDate` | **起点の時刻 ＋ 版の日数**（依頼発は依頼の時刻、業務ルール発は作られた時刻） |
| `Spent` | `Spent(0, 0)` |
| 初期状態 | 作られた |

**版そのものは渡さない。** Repository が返すのは集約ルートだけなので、
`Rule` 集約が「写すものの束」を返し、ファクトリはそれを受け取る。

### 生成と再構成はまったく別

| | 生成 | 再構成 |
|---|---|---|
| いつ | 新しい1件が生まれるとき | 帳簿から読み戻すとき |
| 業務の規則 | **効かせる**（上の表が規則） | **効かせてはいけない** |

**再構成に今の規則を効かせると、きのう書いた行をきょうの規則で弾く。**
効かせるのは型の形だけ。合わなければ「読めない、入れ直せ」と名乗って止まる。
**古い帳簿は捨ててよい**——注入し直せば戻る。だめなのは黙って壊れること。

## 4. interface（**正本**）

**接尾辞が役割を言う。**

| interface | 接尾辞 | 何を出し入れするか | 宣言 | 実装 | 要求者 |
|---|---|---|---|---|---|
| `JobRepository` | Repository | 仕事の集約ルートを鍵で1件 | domain | adapters | 集約: 仕事（I1）／すべての書き込み |
| `RuleRepository` | Repository | 業務ルールの集約ルートを鍵で1件 | domain | adapters | `create`・`add_version`・`activate`（**`run_check` は仕事が写した基準を見る**） |
| `RuleReader` | Reader | 業務ルールの一覧（名・版の番号・有効な版・やること） | **app** | adapters | 予定の画面 |
| `ResultStore` | Store | 成果を積む | domain | adapters | 積む: `submit` ／ 読む: `run_check` |
| `EvidenceStore` | Store | 根拠を積む | domain | adapters | 積む: `submit`・**`confirm`**（確かめ期日に源を読み直す） ／ 読む: `confirm` |
| `QuestionStore` | Store | 質問と回答を積む | domain | adapters | 積む: `ask`・`answer` ／ 読む: `gather_today`・詳細（**`start` は `WorkReader` から読む**） |
| `AssessmentStore` | Store | 見立てを積む | domain | adapters | 積む: `assess` ／ 読む: `gather_today`・詳細 |
| `ClockPort` | Port | いまの時刻を出す | **app** | adapters | **人・AI・時計のすべてと、今日の画面**（`Approval` が「いつ」を要るため） |
| `IdPort` | Port | 新しい識別子を振る | **app** | adapters | `request`・`create` |
| `LlmPort` | Port | LLM に渡し、**`Reply`（印つき）と、使った回数・秒**を受け取る | **app** | adapters | **`consult` だけ** |
| `SourcePort` | Port | 源から読む。**源の言葉を業務の語へ翻訳**（腐敗防止層）。出口は**材料・引用・読めなかった理由**の3つ | **app** | adapters | `consult`・`submit`・**`confirm`**（根拠の引用を取る） |
| `TopicPort` | Port | 題材のデータ（版の中身）を読む | **app** | adapters | `add_version` |
| `ActiveRuleReader` | Reader | 有効な版の識別子と番号を読む | **app** | adapters | `create` |
| `OriginReader` | Reader | 既にある仕事の作成元の鍵を読む | **app** | adapters | `create` |
| `WorkReader` | Reader | **AI が1件こなすのに要る材料**——やること・受け入れ基準・源・答えのある質問・前に出した成果の中身・**落ちた中身と止まった理由の列**・これまでの見立て・使った量と上限・やり直した回数と上限・**確かめ期日**・**同じ `RuleName`・同じ `Period` の、別の版から生まれた仕事の状態** | **app** | adapters | AI が始めるものすべて | まだ居ない（型） | ドメインの型を返していたら赤 |
| `JobStateReader` | Reader | ある状態の仕事の識別子。**担当でも絞れる** | **app** | adapters | `start`・`ask`・`submit`・`fail`・`assess`・`spend`・`hand_out`・`return_timed_out`・`run_check`・`sort_failures`・`confirm`・`mark_overdue` |
| `TodayReader` | Reader | **今日の材料**（今日の行から押せることを除いた欄。正本は[人に見えるもの §2](人に見えるもの.md)） | **app** | adapters | `gather_today` |
| `DetailReader` | Reader | 詳細の材料（出来事の列・質問と回答の本文・見立ての本文・**成果の中身**・**根拠の引用**） | **app** | adapters | 詳細の画面 |

### 決まり

| 決まり | なぜ |
|---|---|
| **Store の「積む」は在りかを返す** | 在りかを別に振ると、振る者と積む者が2つになる |
| **Repository は集約ルートにつき1つ。返すのは集約ルートだけ** | 部品を外に出すと境界の外で書き換えられる |
| **Repository は鍵で1件。一覧と絞り込みは Reader** | 中心の interface に画面の都合が入り込まない |
| **Reader は書かない。返す型は渡す先で決まる**——画面と LLM へは文字と ID、**domain の仕様へは domain の値**（`TodayReader`→今日の材料、`LlmPort`→`Reply`）。宣言が app でも返す型が domain なら**依存は内向き** | 判定の材料を app の型にすると、domain が app を見る |
| **Port は domain に現れない** | 外の道具は指せる不変条件を持たない |
| **要求者の欄が空の interface は置かない** | 誰も呼ばない宣言が、前回いちばん増えた |
| **積む者が空の Store は置かない** | 中身が永久に0件になる（根拠がそうなっていた） |
| **「まだ置かない」という節を作らない** | 置かない理由（「◯◯が一覧に無い」）は消えても気づけない。**実際に4本が理由の消えたまま残った** |

### 依存性逆転

domain が「出し入れできること」を型として宣言し、adapters が内向きに実装する。
**矢印の向きを変えるためだけの仕掛け。**

### 書き込みの門

**姿だけでは呼べない形にする。** 引数は「**新しい姿と、その理由のドメインイベントの列（空でない）**」の対1つ。
空の列がそもそも作れない——これが I1 の実物。列にするのは、1つの遷移で出来事が2つ残る道があるから
（頼む＝`JobRequested`＋`JobCreated`）。
**楽観ロックは口へ漏らさない**。返すのは「書けたか／書けなかったか」だけ。

## 5. ドメインイベント（**正本**）

**過去形。観察だけ。判断を含まない。積むだけ。**

**すべての出来事が「いつ・誰が」を持つ。** 誰が＝`Actor`（人・AI・時計）。
下の表は**それに足して残るもの**だけを書く——共通を書き分けると、どこかで落ちる。

| 出来事 | 何が残るか | 識別子 |
|---|---|---|
| 仕事が頼まれた | 誰が・何を | `JobRequested` |
| 仕事が作られた | どの業務ルールの、どの版の、どの対象期間 | `JobCreated` |
| 仕事が配られた | — | `JobHandedOut` |
| 着手された | 誰が取ったか | `JobStarted` |
| 手放された | 誰が離したか | `JobReleased` |
| 時間切れで戻った | 誰の担当だったか | `JobTimedOut` |
| 成果が出された | 成果の在りか ＋ **根拠の在りか** | `ResultSubmitted` |
| 検査に通った | **誰へ担当が移ったか** | `CheckPassed` |
| 検査で止まった | 止めた理由 | `CheckStopped` |
| **承認された** | — | `Approved` |
| **差し戻された** | 誰が・理由 | `SentBack` |
| 終わった | 根拠の在りか、または確かめ期日 | `JobFinished` |
| **打ち切られた** | 誰が・理由 | `JobAbandoned` |
| 期日を過ぎた | — | `DueDatePassed` |
| 失敗した | 落ちた中身 | `JobFailed` |
| もう一度やった | 何度目か | `Retried` |
| 使った量が増えた | 増えた回数と秒 | `SpentIncreased` |
| 質問された | 何を | `QuestionAsked` |
| **答えられた** | 誰が・何と ＋ **誰の担当が外れたか** | `QuestionAnswered` |
