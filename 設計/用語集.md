# Ichiza（一座）— 用語集

**版**: v1.0（2026-08-21）
**役目**: **業務の語と識別子の対を持つ唯一の場所。** 日本語⇄英語の橋はここだけ。

**ここに載るのは業務の語だけ。** 置き場・口・手順・判定といった**役割の語は載せない**
（前回それを載せて、「タスクの置き場」からコードの名前を作った）。
パターンの名は英語のまま扱い、[ドメインモデル §7](ドメインモデル.md)に住む。

---

## 1. 人と場

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 人 | 判断する者。承認・差し戻し・有効化・回答は人しかできない | `Human` |
| AI | 仕事をこなす側。判断はしない | `Agent` |
| 帳簿 | 起きたことと、いまの姿を持つ場。**書き換えない・消さない** | `Ledger` |

## 2. 仕事

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 仕事 | 頼まれてから終わるまでの1件。一生を持つ | `Job` |
| 仕事の識別子 | その1件を指す。**一意で、あとから変えない** | `JobId` |
| 依頼 | 人が「これをやって」と言った事実 | `Request` |
| 期日 | その仕事を終えるべき時刻 | `DueDate` |
| 担当 | いまその仕事を持っている者。人かAI | `Assignee` |
| 成果 | 仕事が生んだもの。出したら書き換えない | `Result` |
| 根拠 | 終わったと言える裏づけ。**人の申告ではなく、読んで確かめられるもの** | `Evidence` |
| 確かめ期日 | 根拠が無いまま終わりにしたとき、あとで確かめる時刻 | `RecheckDate` |
| 作成元 | その仕事がどこから生まれたか。依頼発か、業務ルール発か。**二度作らないための鍵** | `Origin` |
| 承認 | 人が「進んでよい」と決めた事実。誰が・いつ が必ず残る | `Approval` |
| 差し戻し | 人が「まだだ」と決めた事実。理由が必ず残る | `SendBack` |
| 質問 | 材料が足りないとき、AIが人に尋ねること。**判断は求めない** | `Question` |
| 見立て | AI が状況を読んで書いたもの。**「こうだと思う・こうすべきだと思う」**。事実の報告と案であって、**判断ではない**——決めるのは人 | `Assessment` |
| 回答 | 人が質問に答えた事実。答えは根拠になる | `Answer` |
| 使用上限 | 1件に使ってよい回数と時間。**暴走を止める安全弁**であって、人が読む数字ではない——達したら AI は必ず見立てを書く | `Budget` |
| 使った量 | その仕事がこれまでに使った回数と時間。上限と比べて尽きたかが決まる | `Spent` |

## 3. 決まり

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 業務ルール | 繰り返しやる仕事の決まり。これが仕事を生む | `Rule` |
| 業務ルールの識別子 | その決まりを指す。一意 | `RuleName` |
| 版 | 業務ルールの1つの姿。**積むだけ・書き換えない** | `Version` |
| 有効 | その版でいま仕事を生してよい、という人の判断 | `Active` |
| 周期 | どれくらいの間隔で仕事を生むか（月・週） | `Cycle` |
| 対象期間 | その仕事が担当する期間（2026-08、2026-W34） | `Period` |
| 受け入れ基準 | 何をもって成果とするか | `AcceptanceCriteria` |
| 検査 | 成果が受け入れ基準を満たすかを機械で見ること。**止める力を持つ** | `Check` |

## 4. 観察と判定（中心に住む）

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 出来事 | 起きた事実。過去形。判断を含まない | `Event` |
| 警告 | **いま人の目と判断が要る仕事**。人がいま押せることが無いものは含まない | `Alert` |
| 今日 | いま人の目と判断が要る仕事の集まり | `Today` |

**画面の名前（予定・履歴・詳細・検索）はここに載せない。** 画面の都合であって業務の語ではない
（掟4）。画面は[プレゼンテーション](プレゼンテーション.md)に住む。

## 5. 操作の語（コードの動詞になる）

**誰が起こすかで3つに分かれる**——人・AI・時計。
[アプリケーションサービス](アプリケーションサービス.md)がその一覧で、
**人の分だけが判断**。

| 語 | 一言定義 | 識別子 |
|---|---|---|
| 頼む | 人が仕事を起こす | `request` |
| 承認する | 人が「進んでよい」と決める | `approve` |
| 差し戻す | 人が「まだだ」と決める | `send_back` |
| 答える | 人が質問に答える | `answer` |
| 有効にする | 人が版で仕事を生してよいと決める | `activate` |
| 作る | 業務ルール×対象期間 から仕事を起こす | `create` |
| 配る | 作られた仕事を着手できる状態にする | `hand_out` |
| 着手する | AI が仕事を取り、材料を揃える | `start` |
| 尋ねる | 材料が足りないとき、AI が人に質問を積む | `ask` |
| 落ちる | AI が、落ちた中身を残す | `fail` |
| 手放す | AI が担当を外し、取り直せる状態へ戻す | `release` |
| 見立てを書く | AI が読んだ結果と理由を積む | `assess` |
| 版を積む | 人が業務ルールに版を1つ積む | `add_version` |
| 出す | AI が成果を積み、取れれば根拠も積む | `submit` |
| 検査する | 成果が受け入れ基準を満たすかを機械で見る。**判定そのもの**（ドメインサービス） | `check` |
| 検査を回す | 成果を取り出し、検査にかけ、結果を帳簿へ書く（ユースケース） | `run_check` |
| 時間切れを戻す | 期限の切れた担当を外し、仕事を戻す | `return_timed_out` |
| 失敗を仕分ける | 落ちた仕事を、やり直すか人へ上げるか分ける | `sort_failures` |
| 確かめる | 根拠を読んで終わりにする | `confirm` |
| 今日の分を集める | 人の目と判断が要るものを1箇所で判定する | `gather_today` |

## 6. 使わない語

| 使わない | 代わりに | なぜ |
|---|---|---|
| タスク | 仕事 | 人が「仕事」と言う |
| 定義 | 業務ルール | 「定義」は設計の語で、業務の語ではない |
| 停止点・チェックポイント | 承認待ち | 人が言う言い方に寄せる |
| 証拠 | 根拠 | 同上 |
| 置き場・口・輪・手順・仕立て | **パターンの名をそのまま使う**（Repository・Port・ドメインサービス・アプリケーションサービス・ファクトリ） | 役割の語を日本語にすると、そこからコードの名前を作ってしまう |

## 7. 名前の決まり

- **識別子は英語。** 和名は用語集だけが持つ
- **1語1識別子。** 同じ語に2つの識別子を割り当てない。逆も同じ
- 型と関数の説明文に日本語の語を書く——`grep 根拠` で設計から実装へ辿れるように
- **画面に出るのは日本語の語そのまま。** 画面で言い換えない。読みにくいなら**用語集で改名する**
