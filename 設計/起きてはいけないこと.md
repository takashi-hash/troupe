# Ichiza（一座）— 起きてはいけないこと

**版**: v1.0（2026-08-21）
**役目**: **設計全部の源。** 不変条件も集約の境界も型の作り込みも、ここから導く。

一座は「AI が仕事を回し、**判断は人間**が持つ仕事場」。
だから守るべきものは2種類しかない——**仕事が落ちないこと**と、**判断が人のものであり続けること**。

---

## 1. 一覧

**どう見えたら失敗か**が書けない行は置かない。「〜が正しくない」は失敗の書き方ではない。

| # | 起きてはいけないこと | どう見えたら失敗か |
|---|---|---|
| **F1** | 頼まれた仕事が、誰にも気づかれないまま期日を過ぎる | 期日の過ぎた仕事があるのに、今日の画面に1件も出ていない |
| **F2** | 決まってやる仕事が、人が思い出さないと始まらない | 月次の業務ルールが有効なのに、その月の仕事が作られていない |
| **F3** | 人が判断していないのに、外に出る | 外向きの結果が残っているのに、承認した人と時刻が帳簿に無い |
| **F4** | 何が起きたか説明できない | ある仕事について「誰が・いつ・何を・どうした」を並べられない |
| **F5** | 終わったことになっているのに、終わっていない | 完了と記録されているのに、そう言える根拠を指せない |
| **F6** | 警告が読まれなくなる | 同じ警告が毎日出ていて、人がもう画面を見ていない |
| **F7** | 帳簿が黙って壊れる | 古い記録が読めないのに、エラーも出ず動き続けている |
| **F8** | 検査が嘘をつく | 守っているはずの規則を壊しても、検査が緑のまま |
| **F9** | 設計とプログラムが離れる | 設計に書いてあることが、コードのどこにも無い |

---

## 2. どこから来たか

- **F1・F2・F4** は人の言葉から。「請求とか翌月になる」「今日頼んで明日やる」
  「ルーチンの業務って月で決まっている……AI が勝手に作ってくれる想定」
  「誰がいつ何をどうしたも把握できるようにしないとダメでは？」
- **F3** は公理から。**判断は人間**
- **F5・F6** は F3・F4 の裏——判断したことにする／見なくなる、はどちらも判断を失う道
- **F7・F8・F9** は**一座自身で実際に起きた**。版番号の表を誰も読んでいなかった。
  壊しても緑の検査が2つあった。設計19枚とコード80ファイルが離れて、白紙に戻した

---

## 3. これが何を要求するか

| 失敗 | 要求されるもの |
|---|---|
| F1 | 期日を持つこと。期日の過ぎた仕事を毎日1箇所に集めること |
| F2 | 業務ルールから仕事が自動で作られること。二度作られないこと |
| F3 | 承認が記録として残ること。承認なしに先へ進めないこと |
| F4 | **状態の変化と、その理由の出来事が、必ず一緒に記録されること** ← 集約の境界を要求 |
| F5 | 終わりに根拠が要ること。根拠が無いなら、確かめる期日が要ること |
| F6 | 人が今できることが無いものを出さないこと |
| F7 | 帳簿が自分の形を名乗り、合わなければ開かないこと |
| F8 | 検査は壊して赤を見てから使うこと |
| F9 | 設計の各行に執行者が居ること |

**F4 だけが「境界」を要求している。** 2つのものを1回の書き込みで守れ、と言っているのは
これだけ。[集約](集約と不変条件.md)はここから引く。
