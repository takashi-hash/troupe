# Ichiza（一座）— 設計の読みかた

**版**: v0.9（2026-08-21。v0.9: いちばん上の眺めに カスタム/ と 起動/ を。v0.8: v0.8: 10_画面 は読む5枚。v0.7: v0.7: 掟10 の改名を実地で1回まわし、画面の語 lint を執行者に。v0.5: コードは英語・対訳は1箇所。v0.6: 掟9の最終形——設計文書も識別子で書く。日本語の語は用語集・画面・docstring に住む）
**目的**: 実装と設計を同じリポジトリに同居させる。設計は `設計/` の下に集め、**一目で設計だと分かる**ようにする。

## 3. 置き場の掟

1. **設計はすべて `設計/` の下。** ルート直下に設計ファイルを増やさない（README を除く）。
2. **設計ファイルは和名・全部 .md。** 図は mermaid で md の中に埋める（1成果物＝1ファイルで完結させる）。
3. **参照は前向きのみ。** 後の歩のファイルは前の歩を参照してよい。逆は不可（用語集は Aggregate を知らない）。
4. **空ファイルを先に置かない。** ファイルは歩が来たときに初めて生まれる。フォルダも歩の開始時に切る（教訓5「効かない機能は残さない」・教訓1「宣言に執行者がいなければ実装ではない」）。
5. **決定は、それが効く成果物の中に書く。** 独立した決定記録は既定で作らない。作れるのは §4 の3条件を満たすときだけ。
6. **Custom の設計は混ぜない。** 題材の設計は着手時に `カスタム/<題材>/設計/` を切る（まず `カスタム/運転/`。順はドメインモデル §10——運転→庶務→訪問診療。Foundation は中身を1行も知らない——§8 の線をフォルダでも守る）。
7. **実装は歩7のあとに、リポジトリ直下で始める**（`設計/` と `カスタム/` 以外が実装。層のフォルダは形態マップ §3）。実装中に湧いた設計の疑問は、実装の中で解かずドメインモデル.md §11（未決）へ戻す。
8. **出典を載せない。** 参考にした教材・本・他のプロジェクトの名は設計に書かない。設計は自分の言葉だけで立つ。出典はあくまで参考であり、リポジトリの外に置く。
9. **言葉の正本は用語集。設計とコードはプログラムの言葉で書く。**（前の掟9「設計は一座の言葉」を名指しで覆す）日本語の語と識別子の対を持つのは**用語集だけ**。他の設計文書とコードは、術語を**識別子のまま**書く——地の文の文法は日本語、動詞は「approve する」の形でよい。勝手訳の禁止——訳は用語集の対訳が1箇所で決め、登録の無い識別子は書けない（lint が執行）。型と関数の docstring に日本語の語を書く——grep の錨: `grep Checkpoint` は設計・実装・テストに、`grep 承認待ち` は用語集と docstring に当たる。
10. **画面は別名を作らない。出す語を選ぶだけ。** 画面に出るのは**日本語の語**（用語集の語そのまま。同義語ゼロは画面にも効く）。出してよい語は用語集 §10 の一覧が決め、無い語（Lease・Core・Fingerprint…）は画面に出さない。語が画面に不向きだと分かったら、画面で言い換えず**用語集で改名する**（2026-08-21 に実際にそうした——実地で「読みにくい」と分かり、用語集 v4.0 で日本語の語を一般的な業務システムの語へ一斉に改名。識別子は1つも動かず、コードとテストは無傷だった）。**執行者は `tests/ui_words_lint.py`**——画面の表示が §10 に無ければ赤。画面に出る**中身**は現場の言葉（題材ごと——運転ならリポジトリや依存、診療なら施設や担当医）で、Constitution から来る。

> まとめ: **画面と会話は日本語の語。設計文書とコードは識別子。橋は用語集の1冊だけ。**

## 4. 決定記録の掟 ―― 既定では作らない

決定記録は大抵読まれなくなる。読まれない記録は嘘になる（教訓7「狼少年を作らない」・教訓5「効かない機能は残さない」）。だから:

**決定は、それが効く成果物の中に書く。** 読み返す場所に置かなければ読まれない（教訓1——記録の執行者は読む者）。

- 「認証は買う」→ `三分類表.md` に
- 「履歴を Event の列では持たない」→ `出来事カタログ.md` の冒頭に
- 「実装言語は◯◯」→ `層割当て表.md` の冒頭に

独立した決定記録に昇格できるのは、次の**3つ全部**を満たすときだけ:

1. **覆すと高くつく** —— やり直しがディレクトリ移動で済まない（データ移行・書き直し級）
2. **1つの成果物に収まらない** —— 複数の歩・複数のファイルにまたがって効く
3. **読む者と読む時が言える** —— 「誰が・いつ読み返すか」を1行で書ける。書けなければ作らない

3つ揃って初めて `決定記録/` を切る（それまでフォルダも無い）。作ったものは積むだけ・上書きなし。覆すときは新しい決定で前の決定を名指しで覆す。
