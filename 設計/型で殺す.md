# Ichiza（一座）— 型で殺す

**版**: v1.0（2026-08-21）
**役目**: **書けてはいけないもの**を並べ、型で殺す。

前回はこの表が14行あって、**全部が状態の組み合わせ**だった。
値の行は1つも無く、そのぶん検証が0件になった。
**値の行が無い表は未完成。**

---

## 1. 禁止値

| 書けてはいけない値 | なぜ書けないか | 壊しかた |
|---|---|---|
| 0や負の使用上限 | `Budget` が1以上を要求する | `Budget(calls=0)` を作る |
| 空の担当 | `Assignee` が空を拒む | `Assignee("")` を作る |
| 依頼より前の期日 | `DueDate` が依頼時刻を受け取って比べる | 過去の期日で作る |
| 形の違う対象期間 | `Period` が2つの形しか受け付けない | `Period("来月")` を作る |
| 引用の空な根拠 | `Evidence` が引用を必須にする | 引用なしで作る |
| 誰かいつが欠けた承認 | `Approval` が両方を必須にする | 片方を空で作る |
| 理由の無い差し戻し | `SendBack` が理由を必須にする | 理由なしで作る |
| 空の名前 | `JobId`・`RuleName` が空を拒む | `JobId("")` を作る |
| 月でも週でもない周期 | `Cycle` が列挙 | 3つ目の値を渡す |

## 2. 禁止状態

| 書けてはいけない状態 | なぜ書けないか | 壊しかた |
|---|---|---|
| 承認なしに外へ出た仕事 | 「外へ出た」が `Approval` を材料に必ず持つ | 承認を持たずに作る |
| 根拠も確かめ期日も無い「終わった」 | 「終わった」が2種だけ——根拠つきか、確かめ期日つきか | どちらも無しで作る |
| 担当の無い「実行中」 | 「実行中」が `Assignee` を必ず持つ | 担当なしで作る |
| 作業の材料が無い「着手できる」 | 「着手できる」が材料を必ず持つ | 材料なしで作る |
| 業務ルールから来たのに対象期間が無い仕事 | 「業務ルール発」が `Period` を必ず持つ | 期間なしで作る |
| 版が減った業務ルール | 版は積むだけ。書き込みで前の版列と突き合わせる | 版を1つ消して書く |
| 差し戻された仕事が「承認済み」のまま | 差し戻しは前の状態へ戻す。承認済みへは進まない | 直接その状態を書く |
| 急ぎの印 | **そういう欄が無い。** 急ぎは「期日が今日」で表す | その欄を足そうとする |

---

## 3. 決まり

- **1行が1つの型の仕掛けに対応する。** 「気をつける」は書かない
- **壊しかたが書けない行は置かない。** 壊せないなら、それは禁止できていない
- 型で殺せないものは、ここではなく[集約と不変条件](集約と不変条件.md)へ（結果として見張るもの）
