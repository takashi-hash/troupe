domain が決めた契約（LedgerPort・Aggregate 6つ・AppendOnlyLog・原子性）を SQLite に写す。**スキーマはモデルからほぼ導出**——ここで新しく決めるのは形と索引だけ。

---

## 0. 決定

- **SQLite 1ファイル**（WAL モード）。置き場は `data/ledger.db`（リポジトリ内・git 管理外。バックアップは Mac 標準の仕組みで）
- Aggregate の State は **pydantic の JSON をそのまま1列に**入れる（正規化しない）。読み込みは model_validate——**DB が壊れても型が実行時に弾く**（禁止状態の守りが保存にも効く）
- Artifact・Evidence・Utterance の中身も当面 DB に入れる（小さいテキスト前提。大きくなったらファイル置き場＋参照に切り替え——そのときこの節を覆す）

## 1. 表

**Aggregate（6表、同じ形）**: `jobs` / `definitions` / `boards` / `participants` / `proposals` / `source_registrations`

| 列 | 意味 |
|---|---|
| id TEXT PRIMARY KEY | Aggregate の鍵（Proposal は Fingerprint） |
| state TEXT | pydantic の JSON |
| rev INTEGER | 楽観ロックの版。書き込みごとに +1 |
| updated_at TEXT | — |

**AppendOnlyLog（4表）**: `events` / `artifacts` / `evidences` / `utterances`

| 列 | 意味 |
|---|---|
| seq INTEGER PRIMARY KEY AUTOINCREMENT | 積んだ順 |
| at TEXT | 時刻 |
| kind TEXT | Event の識別子（`JobCreated` など、用語集 §12） |
| job_id TEXT NULL | 絞り込み用（JobSheet がこれで引く） |
| payload TEXT | 中身の JSON |

**索引**:
- `jobs.origin_key TEXT UNIQUE` — **Origin の一意**。二重立ちを DB でも殺す
  - FromDefinition → `def:{definition_name}:{period}`（**version は含めない**——同じ月の Job は版が上がっても1つ）
  - FromInstruction → `utt:{utterance_id}`
  - FromParent → 一意制約なし（親は自分の Lease の中で作るので、冪等は親の実行が持つ）
- `events(job_id, seq)` — JobSheet の時系列引き
- `jobs(state->>'kind')` 相当の状態別索引 — patrol と Outlook の走査用

## 2. 原子性と楽観ロック（掟の実装形）

- **1トランザクション** ＝ Aggregate の UPSERT ＋ AppendOnlyLog への INSERT を**一緒に commit**（Ledger の原子性——外に別の伝送を作らない）
- 楽観ロック: `UPDATE jobs SET state=?, rev=rev+1 WHERE id=? AND rev=?` → 更新行数 0 ＝ **取り合いに負け**（take の決着はこれ。負けた側は読み直して取り直す）
- **AppendOnlyLog の UPDATE / DELETE は SQLite のトリガで拒否**——「積むだけ」を規律でなく DB が強制する（宣言に執行者）
- **接続はスレッドごとに持つ**（2026-08-21、実行して踏んだ）: SQLite の接続はスレッドを跨げない。輪のスレッドと画面のスレッドは別々に開く（1接続＝1参加者）
- **多プロセスの作法**: `busy_timeout` を設定し、**書きトランザクションは BEGIN IMMEDIATE で始める**（読みから書きへ昇格するトランザクションは timeout が有効にならない——Manager・Worker N体・ui が同じファイルに書くための必須設定）
- **検索は全部読んでから絞る**（いまは）: `all_jobs` は完了も含めた全タスクを返し、絞り込みは
  ドメインの仕様（`matches`）が純粋関数でやる。**遅いと実測できたら** SQL 側へ移す
  ——測る前に速くしない（消す前に測る、の裏返し）
- **put は遷移の門**: 書き込む前に旧状態を読み、`required_events`（遷移表の写し）でチェックする——表に無い移りは **IllegalTransition**、必須の Event の欠けは **MissingEvent**。「遷移したのに Event が無い」書き込みは存在できない（4枚と AgreementRate は Event から導出されるので、これが画面が嘘をつかない保証）

## 3. LedgerPort（domain にある口の型）

最小で切る。読む側（枚たち）は別の読み専用クエリ——LedgerPort を太らせない。

```
LedgerPort（場——集約ごとの置き場を差し出すだけ。1つの口に全集約を詰め込まない）:
  jobs: JobRepository            … get / put / find_by_origin / find_by_state
  definitions: DefinitionRepository … get / put / enacted
  boards: BoardRepository        … get / put
  participants: ParticipantRepository … get / put
  artifacts: ArtifactStore       … append / get
  evidences: EvidenceStore       … append / get（完了の根拠。積むだけ）
  events: EventStore             … append

（前の形——1つの口に14メソッド——は集約の境界を口の上で消していたので覆した）
旧:
  get(job_id) → (Job, rev)?                    … 読み。rev は次の put の期待値
  put(job, expected_rev, events) → 成否        … 遷移の門＋楽観ロック＋Event を1トランザクションで
  append(events)                               … AppendOnlyLog への追記だけ
  find_by_origin(key) → job_id?                … create の冪等の要
  find_by_state(kind) → job_id たち            … dispatch・patrol の走査
  get_definition / put_definition(defn, events) … 業務ルールの門: 版は積むだけ・enact は存在する版だけ・
                                                  変化に応じた必須 Event（VersionAppended・DefinitionEnacted）
  enacted_definitions()                        … 有効な業務ルールたち
  get_board / put_board(board, events)         … ボードの門: 方針は積むだけ・freeze の変化に必須 Event
```

**門はすべての Aggregate に**: Job だけでなく Definition・Board の書き込みも「積むだけの破り（AppendOnlyViolation）」「必須 Event の欠け（MissingEvent）」を拒否する。誰が enact / freeze したかは Event が持つ（I5）。

## 4. スキーマの変更

- `schema_version` 表＋番号つき SQL を**前にだけ**反映（積むだけ。書き直さない）
- **番号は効いている**（2026-08-21、段C）: 新しい帳簿は自分の形の番号を刻み、
  番号が違えば開かない——`StaleLedger`「読めない、入れ直せ」
- **古い帳簿は捨ててよい、と決めた**: 注入し直せばボードと業務ルールは戻る。
  移行の仕組みは作らない（**効かない機能は残さない**）。だめなのは**黙って壊れる**ことで、
  そこだけを塞いだ。番号を上げ忘れたときも、行が型に合わなければ同じ声で止まる
- **型を変えたら `SCHEMA_VERSION` を上げる**。上げ忘れは、行が読めなくなった時点で分かる

## 5. テストと評価（この層の流儀）

| 何を | どう壊して赤を見るか |
|---|---|
| 積むだけ | events に UPDATE を打つ → トリガが拒否することをテスト。トリガを消して赤も確認 |
| Origin の一意 | 同じ origin_key で2度 create → 2度目が失敗し、JobCreated が1つであること |
| 楽観ロック | 2つの接続で同じ Job を take → 片方だけ勝つこと。`AND rev=?` を消して赤 |
| 原子性 | put の途中で例外 → Aggregate も Event も**両方**残っていないこと（rollback） |
| 型の守り | DB の state を直接壊す（試みの無い Applied を書く）→ 読み込みの model_validate が弾くこと |
| 遷移の門 | Event 無しの遷移 → MissingEvent。遷移表に無い移り → IllegalTransition。チェックを消して赤も確認 |

評価軸: I4「消えない」・I5「説明できる」の実測はこの表から導く（Event が消えない・JobSheet が全部辿れる）。
