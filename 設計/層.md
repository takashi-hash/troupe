# Ichiza（一座）— 層

**版**: v1.0（2026-08-21）
**役目**: 何をどこに置くかを決める。**依存は内向きのみ。**

**「置いてはいけないもの」を先に書く。** 置いてよいものだけを書くと隙間に何でも入る。
前回は中心 1,539行のうち451行が掟以外だった——外の道具の口・画面の読み・楽観ロック。

---

## 1. 4つの層

| 層 | **置いてはいけないもの** | 置くもの |
|---|---|---|
| **domain**（中心） | **時計・乱数・保存・画面・外の道具**。「いま」は引数で受け取る | 値・エンティティ・集約・不変条件・検査・出来事の名前 |
| **app**（手順） | **業務の規則。** `if` で業務を判断したくなったら中心へ | 人が始める手順・時計が始める手順・ひと仕事の境目・画面へ渡す値への詰め替え |
| **adapters**（外） | **業務の規則。** 翻訳と入出力だけ | 帳簿の実装・外の道具の口とその実装・源の読み |
| **ui**（画面） | **業務の規則。** 並べる・整える・受け取るだけ | 画面の部品。**domain を知らない** |

**「業務の規則を置いてはいけない」が3層に書いてある。** 規則が置けるのは中心だけ。

## 2. 口をどこに置くか

前回いちばん壊れたところ。**中心に12個の口があり、そのうち4つしかリポジトリでなかった。**
LLM の口も画面の読み口も中心に居た。

| 口 | どこに宣言するか | なぜ |
|---|---|---|
| 集約を出し入れする口 | **domain** | 中心が「出し入れできること」を要求するから。実装は adapters |
| 外の道具の口（LLM・源・設定） | **app** | 使うのは手順。中心は外の道具を知らない |
| 画面が読む口 | **app** | 画面へ渡す値を作るのは手順 |

**接尾辞が役割を言う。** `Repository`＝集約の出し入れ、`Store`＝積むだけの列、
`Port`＝外の道具、`Reader`＝参照だけ。

## 3. ロックはどこに置くか

**技術的関心であって、業務の語ではない。** 前回は楽観ロックが中心の口の引数に露出し、
「札（期限で自動的に戻る仕掛け）」が中核に入っていた。

| もの | どこ | なぜ |
|---|---|---|
| 楽観ロック（版数） | **adapters の中に隠す** | 口は「書けたか／書けなかったか」だけを返す |
| 担当が誰か | **domain** | 業務の語 |
| 期限が来たら担当を外す | **app の手順** | 排他制御の仕掛け。業務の判断ではない |

## 4. 画面へ渡すもの

**画面に届くのは文字と ID だけ。** 集約も値オブジェクトも画面へ出さない。
詰め替えるのは **app**——画面が自分で詰め替えると、画面が中心の形を知ることになる
（前回そうなって、中心を直すと画面が壊れた）。

## 5. 中核はどこまでか

**中核に入れてよいのは「業務の判断が要るもの」だけ。**

| 中核 | 中核でない |
|---|---|
| 仕事の一生 | 周期で回すこと（手順） |
| 人の承認と差し戻し | 担当を期限で外す仕掛け（排他制御） |
| 終わったと言える根拠 | 保存の仕組み |
| 業務ルールの版と有効化 | LLM・画面の部品 |

前回は右の列の上2つが左に入っていた。**中核が膨らむと、そのぶん中心が
掟以外のもので埋まる。**
