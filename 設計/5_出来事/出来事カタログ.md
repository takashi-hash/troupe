## 1. 履歴の持ち方（結論）

**Aggregate の State が本体。履歴を Event の列としては持たない。**

- Event は観察の記録であって、State を Event から組み立て直すことはしない
- I5「説明できる」は AppendOnlyLog（Event・Evidence・Artifact・Utterance）＋Job からの参照で足りる
- 「履歴そのものが業務要件」なのはカルテやレセコンの側——それは **Source** のタスクで、Ledger のタスクではない

**名前は型**: この表の識別子が `domain/event.py` の `EventKind` に写っている。打ち間違いは型チェックで落ち、
一覧が用語集 §12 と一致していることは `tests/event_kinds_lint.py` が見張る（状態を型で守ったのと同じ守り）。

## 2. カタログ（すべて過去形。観察であり、判断を含まない）

### Job

| Event | 刻む者 | 載るもの |
|---|---|---|
| `JobCreated` | Manager／Reception／親の Worker | job_id・**Origin** |
| `JobDispatched` | Manager | job_id（Briefing の Check と Gate を通った印） |
| `LeaseTaken`／`LeaseReleased`／`LeaseExpired` | Worker・Human／Worker／Manager | job_id・holder |
| `ProgressLogged` | Worker | job_id・Progress の中身 |
| `JobSubmitted` | Lease の holder | job_id・Artifact への参照（Verifying へ） |
| `InquiryAsked`／`InquiryAnswered` | Worker／宛先の Human | job_id・問い／答えの Utterance への引用 |
| `CheckPassed`／`CheckBlocked` | Check | job_id・Check 名・結果 |
| `ReviewPassed`／`ReviewReturned` | Review する Worker | job_id・理由 |
| `CheckpointReached`／`CheckpointApproved` | Job／担当の Human | job_id・誰が |
| `CheckpointBypassed` | **まだ刻む者が居ない** | job_id（**事故**。赤く見せる）。判定は在る（surface が赤で並べる）が、**出来事としては書いていない**——誰がいつ刻むかが未決（ドメインモデル §11） |
| `JobConfirmed`／`ApplyAttempted`／`JobApplied` | 担当・Worker | job_id・AttemptRecord |
| `JobClosed` | **Manager の confirm**（働き手でも人でもない——証拠を照合した者が閉じる） | job_id・Evidence への参照 |
| `FailureOccurred`／`Retried`／`BudgetExceeded` | Job・Manager | job_id・Environment か Content か |

## 3. 「全部、Ledger 越し」の言い直し（完了条件の確かめ）

- Manager → Worker の Instruction は**存在しない**: `JobCreated`・`JobDispatched` → Worker が `LeaseTaken` を刻む
- Worker → Worker の受け渡し: `JobClosed`（Artifact への参照つき）→ 次の Job の Briefing がその Artifact を指す
- Human への依頼: `CheckpointReached` → MorningSheet に載る → Human が `CheckpointApproved` を刻む
- Human からの Instruction: `UtteranceLogged` → Reception が `InstructionTranscribed`

「誰も直接話さない」は、**すべてこの列の読み書きに還元できる**。
