**版**: v2.3（2026-08-21。v2.3: 構造の名前を英語に（掟9）。v2.2: v2.2: カスタムの置き方と注入（人の操作）。v2.1: v2.1: ui は読む5枚（検索を追加）。v2.0: 術語を識別子に統一）

領域ごとに「どこまでやるか」を割り当てる。**作らないものを、作るものと同じ精度で書く**のがこの表の完了条件。

---

## 1. 割当て

| 領域 | やり方 | 理由 |
|---|---|---|
| **CoreDomain**（Job の一生・Ledger・Definition・Verification・調停） | **作り込む**——型と Aggregate と Check をフルに。ただし**1つの塊**のまま、中の Boundary はフォルダで切る | Boundary は必ず間違える。フォルダなら引き直しが安い |
| **マスタ・設定**（Participant の登録・SourceRegistration・Board の設定） | **素の一覧と出し入れ**。Aggregate を作らない | 業務ルールがほぼ無い。ここに型の城を築くと工数だけ増える |
| **Generic**（LLM 実行基盤・保存・GUI 部品・通知） | **買う・借りる**。既製のものを adapters/ で包むだけ | どこにでもある。競う意味がない |
| **Custom**（題材の中身。順は 運転→庶務→訪問診療） | **データとして注入**——Definition・Constitution・ReadPort の対応表。**コードにしない** | Foundation は1行も知らない（ドメインモデル §8 の線）。次の題材は注入の差し替えで済む |

## 2. 作らないもの

| 作らないもの | なぜ |
|---|---|
| 複数サービスへの分割 | まず1台・1枚の Board（決定済み）。分けるのは組織が要求してから |
| Event の列から State を組み立て直す仕組み | Aggregate の State が本体（歩5で決着）。説明は AppendOnlyLog で足りる |
| マスタ管理の作り込み | 上の表のとおり素の出し入れで足りる |
| 認証の自作 | 当面1台・手元。要るときが来たら借りる |
| 汎用の Alert 基盤・通知基盤 | 出口は MorningSheet 1本。基盤を作るほどの出口が無い |
| 題材を知る Foundation コード | Custom はデータ。Foundation に病名も帳票名もリポジトリ名も書かない |
| 既製のタスク回しエンジンを借りること | 掟がよそのエンジンの設定に散ると、型で殺す戦略が死ぬ（エンジンの State はただの文字列）。1台・十数 State には借り物のほうが大きく、骨組みは小さい。価値は掟にある |

## 3. 置き場（リポジトリの形）

```
Ichiza/
├── 設計/          ← いまのまま
├── pyproject.toml ← プロジェクトの設定（uv・pyright・import-linter・pytest）
├── check.sh       ← 全チェックを1本で回す（依存方向・型・テスト・対訳 lint）
├── domain/        ← 掟の住む中心
├── app/           ← 回す係（輪と Reception）
├── adapters/      ← 口の実装（保存・MCP・LLM・Calendar）
├── ui/            ← 読む5枚と Chat
├── tests/         ← コードのチェック（型写しの確認・例が仕様・対訳 lint）
├── custom/
│   └── 運転/        ← 注入するデータ。**コードにしない**（順は 運転→庶務→訪問診療）
│       ├── board.toml     ← Constitution（目的・非目標・受け入れ基準・言葉）
│       └── rules/*.toml   ← Definition（1本1ファイル。版は積むだけ）
└── launchd/          ← 起動の宣言ファイル（I8 の執行者）
```

**注入は人の操作**（`python main.py inject 運転`）。**自動では走らせない**——
凍結も有効化も人だけの行為なので、その人がこの操作を走らせたことが人の判断になる
（誰が入れたかは出来事に残る）。帳簿を消しても、注入だけでボードは戻る。冪等なので何度でも。

**構造の名前も欄の名も英語**（`custom/` `rules/` `board.toml`——読みかた 掟9）。
**題材と業務ルールの名は現場の言葉**（`運転/` `週次の検査の見張り.toml`）——中身であって構造ではない。**中身が現場の言葉**で、
土台の型への翻訳は `adapters/toml_custom.py` がやる（境界を跨ぐ言葉は必ず翻訳される）。
