# Ichiza（一座）— 語の出どころ

**版**: v1.0（2026-08-21。歩1のやり直しにあたって、**語がどこから来たか**を記録し始めた）
**状態**: 採取の途中。用語集の作り直しはこの記録が育つまで始めない

---

## 0. なぜこの記録が要るか

**言語は発見するもので、決めるものではない。**

前の用語集は299語あったが、**そのほとんどを私（AI）が発明した**。人が口にしたことのない語に
和名を付け、その和名から識別子を作り、そこからプログラムを書いた。だから名前が
「役割」と「使い道」と「画面」を指していて、業務を指していない:

| 前の用語集にあった語 | 何を指していたか |
|---|---|
| タスクの置き場 | 保存の仕組み（Repository） |
| 枚の材料の口 | 読み取りの型（Port） |
| 持ち主のない規則 | 設計の型（DomainService） |
| 仕立て | 生成の型（Factory） |
| 今日の節 | 画面の並び |
| 詳細を作る | 画面の作り方 |

業務の人は誰ひとりこう言わない。**発明を発見のふりで置いていた。**

だからこの記録を先に作る。**出どころの無い語は用語集に入れない。**
出どころとは「人が、いつ、どう言ったか」——引用そのもの。

---

## 1. 掟（この記録の使いかた）

1. **語は人の発言から採る。** 私が言い出した語は、ここに「AI 発案」と印を付けて置く。
   印の付いた語は用語集に入れない——人が同じ語を口にしたときに初めて昇格する
2. **引用は縮めない。** 言い換えると、言い換えた時点で私の語になる
3. **業務の語だけを採る。** 設計の話・進め方の話に出た語（ドメイン・集約・アンチパターン…）は
   業務の語ではない。それらは英語のまま設計の言葉として扱い、和名を作らない
4. **画面の語も、使い道の名も、ここには来ない。** 画面に何と出すかは、業務の語が決まってから

## 3. 採れていないもの（ここが空いている）

人の発言に一度も出ていないので、**採りようがない**。前はここを全部私が埋めた。

| 空いているところ | 前に私が置いていた語（発明） |
|---|---|
| 仕事が始まってから終わるまでの、途中の呼び名 | 作成済み・未着手・実行中・検証中・承認待ち・承認済み・反映中・反映済み・完了 |
| 「終わった」と言える根拠 | 証拠・自己申告・引用・指紋 |
| 人が止める点 | 承認待ち・承認・停止点 |
| 仕事を生む決まりの呼び名 | 業務ルール・版・有効化・方針・受け入れ基準 |
| うまくいかなかったときの呼び名 | 環境エラー・内容エラー・再試行・使用上限 |
| 働く相手の呼び名 | 機体・働き手・マネージャー・受付 |
| 仕事の材料の呼び名 | 源・読み口・作業情報・成果物 |

**この表が埋まるまで、用語集は作れない。**

## 4. 採るための問い（人に聞くこと）

**出来事から聞く**——過去形の事実は、人がいちばん言いやすい形だから。
「何がある」ではなく「**この前、何が起きたか**」を聞く。

1. この1か月で、あなたが人に頼んだ仕事を3つ、実際の言い方のまま挙げてください
2. その仕事は、頼んでから終わるまでに**どんな段階**を通りましたか。段階の名前を、
   ふだん使っている言い方で
3. 「終わった」とあなたが判断したのは、**何を見たとき**ですか
4. 途中であなたが**止めて確認した**ことはありますか。それをふだん何と呼びますか
5. うまくいかなかった仕事はありましたか。**何がうまくいかなかった**のか、
   その言い分けをふだんどう呼び分けていますか
6. 毎月・毎週決まってやる仕事を、**その一覧の呼び名**ごと教えてください
7. その仕事を「やる」と決めているのは何ですか（決まり・取り決め・手順書…
   ふだんの呼び名で）

答えは荒くてかまわない。**言い換えずに書き取る**のがこちらの仕事。

## 5. 前の設計の扱い

捨てない。**下敷きにする。**

- **残るもの**: 集約の考え方・不変条件の立て方・依存の向き・執行者を置く癖・
  壊して赤を見る。これらは業務の語に依らない
- **捨てるもの**: 語の一覧そのもの。299語のうち、出どころのあるものは17語だった
- **順番も変える**: 前は「用語集 → 境界 → 部品 → 集約」で、用語集を私が書いて始めた。
  今回は**出来事から**始める（§4 の問い）——出来事は人の言葉で出てくるから
